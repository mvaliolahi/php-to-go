اجرای برنامه و ساخت فایل خروجی

همانطور که تا اینجا گفته شد در Go برخلاف PHP که فایل‌ها را مستقیماً روی سرور تفسیر می‌کنید برنامه‌ها معمولاً کامپایل می‌شوند. با این حال ابزارهای مختلفی برای توسعه و اجرا در اختیار دارید:

go run

دستور go run برای اجرای سریع و موقتی کد بدون اینکه فایل اجرایی جداگانه تولید شود استفاده می‌شود. این دستور کد را پشت صحنه کامپایل کرده و بلافاصله اجرا می‌کند.

در صورت موفقیت فایلی با نام ماژول یا پوشه‌ی جاری ساخته می‌شود (مثلاً myapp یا main) که سپس می‌توانید آن را اجرا کنید یا روی سیستم دیگری deploy کنید. برخلاف PHP که به مفسر نیاز دارد، فایل اجرایی Go نیاز به هیچ runtime یا نصب زبانی ندارد و فقط داشتن آن فایل باینری کافی است.

مراحل کامپایل در Go

وقتی go build اجرا می‌کنید، کامپایلر Go چندین مرحله را پشت صحنه طی می‌کند. درک این مراحل به شما کمک می‌کند تا بهینه‌سازی‌های کامپایلر و رفتار برنامه‌ی خود را بهتر بشناسید:

۱. Parsing: کد منبع Go به token تجزیه می‌شود و سپس AST ساخته می‌شود. در این مرحله خطاهای نحوی شناسایی می‌شوند.

۲. Type Checking: کامپایلر نوع تمام عبارت‌ها را استنتاج و بررسی می‌کند. مطمئن می‌شود که انواع با هم سازگار هستند، interface ها به‌درستی پیاده‌سازی شده‌اند و قواعد تایپ سیستم رعایت شده‌اند.

۳. SSA Generation (تولید SSA): AST به فرم میانی Static Single Assignment (SSA) تبدیل می‌شود. در SSA هر متغیر فقط یک بار مقداردهی می‌شود که این امکان بهینه‌سازی‌های قدرتمندی را فراهم می‌کند. می‌توانید SSA تولیدشده را با GOSSAFUNC=main go build مشاهده کنید.

۴. Optimization: چندین پاس بهینه‌سازی روی SSA اعمال می‌شود شامل: dead code elimination، inlining، فرار از escape analysis و بهینه‌سازی حلقه‌ها.

۵. Code Generation: SSA بهینه‌شده به دستورالعمل‌های ماشین متناسب با معماری هدف (amd64, arm64, ...) تبدیل می‌شود.

۶. Linking: لینکر تمام آبجکت‌فایل‌ها و کتابخانه‌ی runtime را با هم ترکیب می‌کند و یک باینری نهایی تولید می‌شود. لینکر Go کاملاً توسط خود تیم Go نوشته شده و به ابزارهای خارجی وابسته نیست.

نکته فنی: برای مشاهده‌ی مراحل کامپایل می‌توانید از پرچم‌های زیر استفاده کنید: go build -gcflags="-m" برای مشاهده‌ی تصمیمات escape analysis و inlining، go build -gcflags="-S" برای مشاهده‌ی خروجی اسمبلی و go build -x برای مشاهده‌ی تمام دستورات اجراشده.

لینکر در Go

لینکر Go یکی از منحصربه‌فردترین بخش‌های toolchain است. برخلاف زبان‌هایی مثل C که از لینکر سیستم ld استفاده می‌کنند، Go لینکر اختصاصی خود را دارد. این لینکر:

۱. باینری استاتیک تولید می‌کند: به‌صورت پیش‌فرض، فایل اجرایی Go هیچ وابستگی دینامیک به کتابخانه‌های سیستمی (مثل glibc) ندارد. این یعنی باینری روی هر توزیع لینوکسی قابل اجراست.

۲. runtime را لینک می‌کند: Go runtime (شامل garbage collector، scheduler و سیستم goroutine) مستقیماً در باینری تعبیه می‌شود. به همین دلیل باینری Go نسبتاً بزرگ است (معمولاً ۵ تا ۱۵ مگابایت) حتی برای برنامه‌های ساده.

مقایسه با PHP: در PHP مفهوم کامپایل متقاطع وجود ندارد چون کد PHP به‌صورت تفسیری اجرا می‌شود و به مفسر نصب‌شده روی سرور هدف وابسته است. اما در Go باینری نهایی شامل تمام وابستگی‌ها (حتی runtime) است و بدون هیچ پیش‌نیازی روی سیستم هدف اجرا می‌شود. این تفاوت یکی از بزرگترین مزیت‌های Go برای دیپلوی است.

Build Modes

Go از چندین build mode پشتیبانی می‌کند که با پرچم -buildmode مشخص می‌شوند:

default: باینری اجرایی استاندارد — حالت پیش‌فرض.

pie: Position-Independent Executable — ASLR در محیط‌های تولیدی توصیه می‌شود.

plugin: تولید پلاگین قابل بارگذاری پویا (فقط لینوکس) — مشابه concept extension در PHP اما بسیار ابتدایی‌تر.

c-archive: تولید کتابخانه‌ی C استاتیک — برای فراخوانی کد Go از C یا Python.

c-shared: تولید کتابخانه‌ی مشترک C (.so/.dll) — برای استفاده‌ی Go به‌عنوان library در زبان‌های دیگر.

نکته: حالت pie در بسیاری از توزیع‌های لینوکس به‌صورت پیش‌فرض فعال است (مثل Fedora و Ubuntu). اگر باینری شما برای محیط‌های با الزامات امنیتی بالا (مثل Docker images سخت‌گیرانه) ساخته می‌شود، -buildmode=pie را در نظر بگیرید.

Build Tags و محدودسازی کامپایل

Race Detector

Go ابزار داخلی قدرتمندی برای شناسایی data race دارد. data race زمانی رخ می‌دهد که دو goroutine همزمان به یک حافظه دسترسی داشته باشند و حداقل یکی از آن‌ها عمل نوشتن انجام دهد. این باگ‌ها به‌سختی قابل تشخیص هستند چون ممکن است فقط در شرایط خاص تکرار شوند.

هشدار: Race detector فقط در زمان توسعه و تست استفاده می‌شود، نه در تولید. این ابزار overhead حافظه‌ی ۵ تا ۱۰ برابری و کاهش سرعت ۲ تا ۲۰ برابری دارد. اما ارزش آن بی‌نظیر است — مسابقه داده‌ای که در تست کشف نشود، در تولید باگ‌های غیرقابل تکرار ایجاد می‌کند.

خط لوله‌ی کامپایل Go: از منبع تا باینری

همان‌طور که در بخش «مراحل کامپایل در Go» دیدید، کامپایلر Go کد منبع را طی چندین مرحله‌ی پیوسته (Parsing → Type Checking → SSA → Optimization → Code Generation → Linking) به فایل باینری اجرایی تبدیل می‌کند. نمودار زیر این خط لوله را به‌صورت بصری به همراه مقایسه‌ی سه دستور go build، go run و go install نشان می‌دهد.

سناریوهای عملیاتی

  • ساخت برای پلتفرم‌های مختلف: با تنظیم GOOS و GOARCH می‌توانید باینری مخصوص هر سیستم‌عامل و معماری را تولید کنید. مثلاً GOOS=linux GOARCH=amd64 go build -o app-linux یک باینری لینوکس تولید می‌کند و GOOS=windows GOARCH=amd64 go build -o app.exe باینری ویندوز می‌سازد. این امکان بدون هیچ ابزار اضافی در دسترس است.
  • کاهش اندازه‌ی باینری با -ldflags="-s -w": پرچم -s جدول نمادها و -w اطلاعات دیباگ DWARF را حذف می‌کند. ترکیب این دو معمولاً ۲۰ تا ۳۰ درصد از اندازه‌ی باینری می‌کاهد. برای تولید، این پرچم‌ها ضروری هستند.
  • استفاده از go install برای ابزارهای سراسری: دستور go install باینری را در GOPATH/bin قرار می‌دهد و از هر مسیری قابل اجراست. این روش برای نصب ابزارهایی مثل golangci-lint یا air ایده‌آل است.
  • کامپایل شرطی با build tags: با //go:build می‌توانید فایل‌هایی بنویسید که فقط در شرایط خاصی کامپایل شوند. مثلاً پیاده‌سازی متفاوت برای Linux و Windows یا فعال‌سازی حالت دیباگ با go build -tags=debug.
  • درک کش ساخت (build cache): Go نتایج کامپایل را در ~/.cache/go-build ذخیره می‌کند. بیلدهای بعدی فقط فایل‌های تغییرکرده را دوباره کامپایل می‌کنند. دستور go clean -cache کش را پاک می‌کند.
نکته‌ی عملی: برای باینری‌های تولیدی حتماً از -ldflags="-s -w" استفاده کنید تا اندازه کاهش یابد. همچنین با -X main.version=1.2.3 می‌توانید اطلاعات نسخه را در زمان ساخت تزریق کنید. ترکیب کامل: go build -ldflags="-s -w -X main.version=$(git describe --tags) -X main.commit=$(git rev-parse --short HEAD)" -trimpath -o myapp. پرچم -trimpath مسیرهای محلی را از باینری حذف می‌کند که برای تکرارپذیری بیلد و امنیت مهم است.
نکته‌ی حرفه‌ای — تفاوت go build، go install و go run: go run برای توسعه‌ی سریع استفاده می‌شود، کد را کامپایل می‌کند، اجرا می‌کند و سپس باینری موقت را پاک می‌کند. go build باینری پایدار در دایرکتوری جاری می‌سازد و مناسب CI/CD است. go install باینری را در GOBIN (یا GOPATH/bin) نصب می‌کند تا از هر مسیری قابل اجرا باشد — این بهترین روش برای نصب ابزارهای توسعه مثل golangci-lint یا air است. در Go 1.24 به بعد، ابزارهای پروژه‌ای را با دستورالعمل tool در go.mod مدیریت کنید (به بخش ۳.۲ مراجعه کنید) تا نسخه‌ی ابزار بین اعضای تیم ثابت بماند.
