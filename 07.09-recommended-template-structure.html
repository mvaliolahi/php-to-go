ساختار پیشنهادی برای قالب‌ها

در این ساختار فایل layout.html نقش اسکلت اصلی صفحه را دارد و فایل‌های دیگر مانند home.html بخش محتوای متغیر را تعریف می‌کنند.

نقش block و define در وراثت قالب

سیستم وراثت قالب در Go بر اساس سه دستور کار می‌کند:

{{ define "name" }}: تعریف یک قالب جزئی با نام مشخص. این قالب می‌تواند با {{ template "name" . }} در جایی دیگر فراخوانی شود.

{{ block "name" . }}default{{ end }}: تعریف یک بلوک با محتوای پیش‌فرض. اگر قالب دیگری با همان نام define شده باشد، محتوای آن جایگزین پیش‌فرض می‌شود. این معادل @yield در Blade است.

{{ template "name" . }}: فراخوانی یک قالب جزئی. نقطه (.) در انتها داده‌های context را به قالب فراخوانی‌شده ارسال می‌کند.

مقایسه با Laravel Blade: در Blade از @extends برای مشخص کردن طرح اصلی و @section/@yield برای تعریف و نمایش بخش‌های متغیر استفاده می‌شود. در Go از {{ block }} با محتوای پیش‌فرض و {{ define }} برای بازنویسی استفاده می‌شود. رویکرد Go ساده‌تر است اما انعطاف کمتری دارد.
یادداشت: تفاوت کلیدی {{ template "x" . }} و {{ block "x" . }}...{{ end }}: template یک قالب از پیش تعریف‌شده را فراخوانی می‌کند (بدون محتوای پیش‌فرض) و اگر قالبی با آن نام وجود نداشته باشد، خطا می‌دهد. اما block هم یک قالب تعریف می‌کند هم آن را فراخوانی می‌کند، و اگر قالب فرزند آن را با define بازنویسی نکند، محتوای پیش‌فرض خودش نمایش داده می‌شود. به‌خاطر داشته باشید که {{ template "x" }} بدون پاس دادن نقطه (.)، داده‌های context را به قالب فرزند نمی‌فرستد و . در داخل قالب فرزند برابر nil خواهد بود — یک منشأ رایج باگ در قالب‌های Go.

الگوی وراثت قالب با block و define

وراثت قالب یکی از الگوهای کلیدی برای جلوگیری از تکرار کد است. در Laravel Blade از @extends و @yield/@section استفاده می‌شود. در Go این الگو با ترکیب {{ block }} و {{ define }} پیاده‌سازی می‌شود. قالب پایه بلوک‌هایی با محتوای پیش‌فرض تعریف می‌کند و هر صفحه می‌تواند آن‌ها را بازنویسی کند:

مهم: در الگوی بالا، فایل home.html بلوک‌های title و content را بازنویسی می‌کند اما head و scripts را نه — بنابراین آن‌ها محتوای پیش‌فرض (خالی) را نمایش می‌دهند. این رفتار مشابه @section اختیاری در Blade است.

Partials

قالب‌های جزئی بخش‌های تکراری مثل هدر، فوتر، منو و کارت محصول هستند. این قالب‌ها با {{ define }} تعریف و با {{ template }} فراخوانی می‌شوند. تفاوت با بلوک‌ها این است که قالب‌های جزئی همیشه محتوای ثابت دارند و قابل بازنویسی نیستند:

ترکیب وراثت قالب و جزئیات رندر

سیستم قالب‌بندی Go بر اساس ترکیب قالب‌ها کار می‌کند، نه وراثت کلاسیک مثل Laravel Blade. قالب پایه (base.html) بلوک‌هایی با محتوای پیش‌فرض تعریف می‌کند و قالب‌های محتوا (home.html و about.html) آن‌ها را بازنویسی می‌کنند. کلید درک این سیستم، فهمیدن نحوه‌ی ترکیب {{ define }} و {{ block }} و {{ template }} است. قالب پایه با {{ block "content" . }}...{{ end }} یک بلوک با پیش‌فرض تعریف می‌کند و قالب محتوا با {{ define "content" . }}...{{ end }} آن را جایگزین می‌کند. رندر نهایی همیشه با ExecuteTemplate(w, "base.html", data) انجام می‌شود، نه با نام قالب محتوا.

سناریوهای عملیاتی

  • ایجاد قالب پایه (base layout): یک فایل base.html با بلوک‌های {{ block "title" . }} و {{ block "content" . }} و {{ block "scripts" . }} بسازید. تمام صفحات از این قالب پایه ارث‌بری می‌کنند و فقط بلوک‌های موردنیاز را بازنویسی می‌کنند. این الگو از تکرار کد HTML در هر صفحه جلوگیری می‌کند.
  • سازمان‌دهی فایل‌های قالب: قالب‌ها را در زیرپوشه‌های layouts/ و pages/ و partials/ تفکیک کنید. قالب‌های پایه در layouts/، صفحات در pages/ و اجزای مشترک مثل هدر و فوتر در partials/ قرار می‌گیرند.
  • استفاده از block با محتوای پیش‌فرض: بلوک‌هایی مثل {{ block "scripts" . }}{{ end }} با محتوای خالی پیش‌فرض تعریف کنید. صفحاتی که نیاز به اسکریپت خاص دارند آن را بازنویسی می‌کنند و بقیه از پیش‌فرض خالی استفاده می‌کنند. این رفتار مشابه @section اختیاری در Blade است.
  • ترکیب قالب‌ها با چندین بخش: قالب پایه می‌تواند چندین بلوک داشته باشد: title و head و content و sidebar و scripts. هر صفحه فقط بلوک‌های موردنیازش را تعریف می‌کند و بقیه از پیش‌فرض استفاده می‌شود.
  • اجزای مشترک (partials): هدر، فوتر، منوی ناوبری و کارت محصول را با {{ define "partial.header" }} تعریف و با {{ template "partial.header" . }} در قالب پایه فراخوانی کنید. این اجزا همیشه محتوای ثابت دارند و قابل بازنویسی نیستند.
نکته‌ی عملی: همیشه یک قرارداد مشخص برای نام‌گذاری قالب‌ها تعریف کنید. مثلاً base.layout.html برای قالب پایه، partial.header.html برای اجزای مشترک و نام صفحه برای قالب‌های محتوا. مهم‌تر از همه، همیشه ExecuteTemplate را با نام قالب پایه (base.layout.html) فراخوانی کنید، نه با نام قالب محتوا. قالب محتوا فقط بلوک‌ها را تعریف می‌کند و به‌تنهایی قابل رندر نیست.
