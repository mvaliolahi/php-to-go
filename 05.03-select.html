Select

چکیده: select برای چندگانه‌سازی channel‌ها و مدیریت چند عمل همزمان استفاده می‌شود. این بخش الگوهای select با default، timeout و done را پوشش می‌دهد. کاربردهای عملی برای timeout و cancellation بررسی می‌شود.

دستور select یک ساختار کنترلی ویژه برای مدیریت هم‌زمان چند کانال است. این دستور شبیه حالتی عمل می‌کند که در یک سیستم صف مانند Laravel چندین worker در حال گوش دادن به صف باشند و هر کدام که زودتر آماده شود job را دریافت کند.

select به شما اجازه می‌دهد عملیات ارسال و دریافت روی کانال‌های مختلف را به صورت هم‌زمان تحت نظر داشته باشید و اولین کانالی که داده‌ای برای پردازش آماده کند انتخاب می‌شود.

اگر چند کانال به طور هم‌زمان آماده باشند Go یکی از آن‌ها را به صورت تصادفی اجرا می‌کند تا تعادل میان کانال‌ها حفظ شود. در صورتی که هیچ کانالی آماده نباشد اگر بخش default تعریف شده باشد اجرای آن بلاک بلافاصله انجام می‌شود و در غیر این صورت select منتظر می‌ماند تا یکی از کانال‌ها آماده شود.

این قابلیت امکان پیاده‌سازی الگوهایی مانند multiplexing برای دریافت داده از منابع مختلف، مدیریت زمان‌بندی و اعمال timeout یا cancellation و همچنین طراحی سیستم‌های non locking را فراهم می‌کند.

وقتی داده‌ای از ch1 دریافت شد اجرا می‌شود، وقتی می‌توان داده‌ای به ch2 ارسال کرد اجرا می‌شود، و اگر هیچ موردی آماده نبود اجرا می‌شود (non-blocking).

در این مثال دو Goroutine پس از زمان‌های متفاوت داده را در دو کانال قرار می‌دهند. select روی هر دو کانال به صورت همزمان منتظر می‌ماند و اولین کانالی که داده‌ای آماده داشته باشد انتخاب می‌شود.

این رفتار در عمل نوعی multiplexing یعنی گوش دادن هم‌زمان به چند منبع و واکنش سریع به اولین منبعی که پاسخ می‌دهد است.

5.3.3 Multiplexing چندین کانال

یکی از الگوهای قدرتمند select توانایی گوش دادن همزمان به چندین کانال است. این الگو وقتی مفید است که داده‌ها از چند منبع مختلف می‌آیند و باید به یک جریان واحد تبدیل شوند:

تنظیم کانال روی nil وقتی بسته می‌شود یک الگوی استاندارد در Go است. کانال nil در select هرگز آماده نمی‌شود و عملاً از رقابت حذف می‌شود. این تکنیک اجازه می‌دهد بدون ساخت Goroutine اضافی، از چند کانال به‌صورت داینامیک دریافت کنید.

جزئیات داخلی — پیاده‌سازی select: دستور select در runtime زبان Go توسط ساختار داده‌ای به نام runtime.scase پیاده‌سازی می‌شود. هر case در select تبدیل به یک scase می‌شود که شامل اطلاعات کانال، جهت عملیات (ارسال یا دریافت) و مقدار مورد نظر است. فرآیند اجرای select به این شکل است:
  • مرحله ۱ — قفل‌گیری: تمام channel‌های موجود در caseها به ترتیب آدرس حافظه قفل می‌شوند (برای جلوگیری از deadlock).
  • مرحله ۲ — بررسی تصادفی: مورد‌ها به ترتیب تصادفی (با استفاده از runtime.fastrand) بررسی می‌شوند. اگر هر کدام آماده باشند بلافاصله اجرا می‌شوند. این ترتیب تصادفی تضمین می‌کند که هیچ case‌ای به صورت سیستماتیک اولویت نداشته باشد و از starvation جلوگیری شود.
  • مرحله ۳ — مسدودسازی: اگر هیچ case‌ای آماده نبود و default وجود نداشت، goroutine فعلی به عنوان waiter در صف sendq یا recvq تمام channel‌های مورد نظر ثبت می‌شود و به وضعیت _Gwaiting می‌رود. وقتی یکی از channel‌ها آماده شود، goroutine بیدار شده و عملیات مربوطه انجام می‌شود.
نکته مهم: هزینه‌ی یک select خالی (بدون case) مساوی با block دائمی goroutine است و منجر به deadlock می‌شود. همچنین select با default خالی معادل runtime.Gosched عمل می‌کند و فرصتی برای scheduler فراهم می‌سازد تا goroutine دیگری اجرا شود.
قوانین مهم select:
  • هر case باید یک عملیات کانال باشد (ارسال یا دریافت).
  • اگر چند case آماده باشند، یکی به‌صورت تصادفی انتخاب می‌شود.
  • بدون default، select بلاک می‌شود تا یکی از case‌ها آماده شود.
  • با default، select بلافاصله برمی‌گردد اگر هیچ case‌ای آماده نباشد.
  • select خالی (select{}) برای همیشه بلاک می‌کند — فقط برای جلوگیری از خروج main() استفاده می‌شود.
  • هرگز time.After را در حلقه بدون بازیافت Timer استفاده نکنید — باعث نشت حافظه می‌شود.

5.3.4 ارزیابی و Multiplexing در Select — جزئیات عملیاتی

همان‌طور که در ابتدای این بخش دیدیم، select تمام case‌ها را به‌صورت تصادفی بررسی می‌کند و اولین case آماده را اجرا می‌کند. این رفتار دقیقاً مشابه الگوی epoll در سیستم‌عامل لینوکس است که در آن چندین file descriptor به صورت همزمان تحت نظر قرار می‌گیرند و اولین رویداد آماده پردازش می‌شود.

در نمودار زیر خط زمانی یک select در حلقه را مشاهده می‌کنید که در هر تکرار case متفاوتی انتخاب می‌شود.

در نمودار بالا مشاهده می‌کنید که در هر تکرار حلقه، select وضعیت آماده بودن تمام کانال‌ها را بررسی می‌کند و بر اساس اولین case آماده، مسیر اجرا را تعیین می‌کند. در تکرار دوم که هر دو ch1 و ch2 آماده هستند، Go به صورت تصادفی یکی را انتخاب می‌کند تا از starvation جلوگیری شود.

تکرار چهارم نشان می‌دهد که وقتی هیچ کانالی آماده نیست و default وجود دارد، select بدون بلاک شدن مسیر default را طی می‌کند.

این رفتار برای پیاده‌سازی الگوهای non-blocking بسیار مفید است زیرا به شما اجازه می‌دهد همزمان با انتظار روی کانال‌ها، کارهای دیگر را نیز انجام دهید.

سناریوهای عملیاتی select

  • Multiplexing چند منبع داده: وقتی داده‌ها از چند منبع مختلف مانند API‌های مختلف، WebSocketها یا صف‌های پیام وارد می‌شوند، select اجازه می‌دهد همه منابع را به صورت همزمان گوش دهید و اولین پاسخ را پردازش کنید. این الگو در سیستم‌های fan-in بسیار کاربردی است و مشابه داشتن چند worker در Laravel Queue است که هر کدام از صف متفاوتی کار می‌گیرند.
  • الگوی timeout برای عملیات کند: با ترکیب select و time.After می‌توانید حداکثر زمان انتظار برای هر عملیات را تعیین کنید. اگر درخواست شبکه یا پردازش سنگین بیش از حد مجاز طول کشید، مسیر timeout فعال شده و می‌توانید خطای مناسب را برگردانید. این الگو در سیستم‌های توزیع‌شده ضروری است زیرا هیچ عملیاتی نباید بی‌نهایت منتظر بماند.
  • ارسال و دریافت non-blocking با default: وقتی نمی‌خواهید goroutine فعلی بلاک شود، default به شما اجازه می‌دهد در صورت عدم آمادگی کانال، مسیر جایگزین را طی کنید. این الگو برای heartbeat، rate limiting و سیستم‌های event loop بسیار مفید است.
  • لغو عملیات با select و context.Done(): با اضافه کردن case <-ctx.Done() به select، می‌توانید عملیات جاری را به صورت ایمن لغو کنید. این الگو به شما اجازه می‌دهد درخواست‌های شبکه، پردازش‌های طولانی یا عملیات I/O را با سیگنال لغو متوقف کنید و منابع سیستم را آزاد نمایید. در PHP معادل این کار pcntl_signal یا process timeout است اما بسیار ساده‌تر و ایمن‌تر.
کانال‌های nil در select: یک کانال nil هرگز در select انتخاب نمی‌شود. این ویژگی به شما اجازه می‌دهد case‌هایی را به صورت داینامیک غیرفعال کنید. مثلاً وقتی یک کانال بسته می‌شود، متغیر کانال را برابر nil قرار دهید تا آن case از رقابت حذف شود. این تکنیک در الگوی fan-in بسیار کاربردی است (جزئیات بیشتر در بخش قبل).
یادداشت: اگر در select چند case هم‌زمان آماده باشند، Go یکی را به‌صورت تصادفی انتخاب می‌کند — نه به ترتیب نوشتن در کد. این رفتار برخلاف switch معمولی است که اولین case منطبق را اجرا می‌کند. اگر نیاز به اولویت بین کانال‌ها دارید، باید از الگوی select تو در تو استفاده کنید: ابتدا یک select فقط روی کانال پر‌اولویت با default خالی می‌نویسید (غیربلاک‌کننده)، و اگر آماده نبود، select دوم روی همه کانال‌ها انجام می‌دهید. این تکنیک برای پیاده‌سازی صف‌های اولویت‌دار یا priority channels ضروری است.
خلاصه‌ی نکات کلیدی:
  • select مانند switch اما برای channel
  • case اولین آماده را اجرا می‌کند
  • default برای non-blocking operation
  • timeout با time.After در select
  • select با done channel برای cancellation
