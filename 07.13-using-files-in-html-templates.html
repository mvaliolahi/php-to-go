استفاده از فایل‌ها در قالب HTML

چکیده: این بخش استفاده از فایل در template را پوشش می‌دهد: include، partial و embed. الگوی base + content و block override بررسی می‌شود. کاربردهای ساختار پروژه پوشش داده می‌گردد.

در فایل HTML جاسازی‌شده یا تولیدی، به فایل‌های استاتیک ارجاع می‌دهیم:

7.13.1 Cache Busting

وقتی از هدرهای کش قوی استفاده می‌کنید مرورگر فایل‌ها را برای مدت طولانی ذخیره می‌کند. مشکل اینجاست که اگر فایل CSS یا JS را تغییر دهید کاربران ممکن است نسخه قدیمی را ببینند. راه‌حل استاندارد افزودن نسخه یا هش به نام فایل است:

7.13.2 تولید هدر کش برای فایل‌های جاسازی‌شده

چون فایل‌های جاسازی‌شده با embed هرگز تغییر نمی‌کنند (مگر با کامپایل مجدد)، می‌توانید هدرهای کش بسیار بلندمدت تنظیم کنید.

پیاده‌سازی کامل embeddedCacheMiddleware با هدر Cache-Control: public, max-age=31536000, immutable و ترفند ldflags برای تزریق نسخه برنامه را در بخش ۷.۱۲ دیدید؛ همان الگو اینجا نیز کاربرد دارد.

نکته: هدر immutable به مرورگر می‌گوید که فایل هرگز تغییر نمی‌کند و نیازی به revalidation ندارد. این هدر فقط زمانی مناسب است که مطمئن باشید فایل واقعاً تغییر نمی‌کند — مثل فایل‌های جاسازی‌شده در باینری. ترکیب آن با cache busting (هش در نام فایل یا پارامتر کوئری نسخه) تضمین می‌کند که پس از بیلد جدید، مرورگرها فایل جدید را بارگذاری کنند.

7.13.3 نکات امنیتی

استفاده از embed برای سرو کردن فایل‌های استاتیک در Go، روش مدرن، ایمن و قابل‌اتکایی است که مخصوصاً برای single binary deployment بسیار مفید است. ترکیب این روش با caching سمت مرورگر باعث افزایش قابل‌توجه سرعت لود صفحات، کاهش مصرف پهنای باند و بهبود تجربه کاربری می‌شود.

7.13.4 جاسازی CSS و JS درون قالب‌ها

گاهی اوقات برای کاهش تعداد درخواست‌های HTTP یا برای تولید صفحات مستقل، نیاز دارید CSS و JS را مستقیماً درون قالب HTML قرار دهید. با ترکیب embed.FS و توابع سفارشی قالب، می‌توانید فایل‌های CSS و JS را بخوانید و درون تگ‌های <style> و <script> قرار دهید:

یادداشت: این الگو را فقط برای critical CSS (سبک‌های بالای صفحه که برای رندر اولیه لازم هستند) یا اسکریپت‌های کوچکِ راه‌انداز استفاده کنید — نه برای همه‌ی فایل‌ها. درlining همه‌ی CSS/JS باعث می‌شود حجم HTML به‌شدت افزایش یابد و مرورگر نتواند هیچ فایلی را کش کند. الگوی بهینه: critical CSS را inline کنید و بقیه‌ی فایل‌ها را به‌صورت لینک خارجی با هدر Cache-Control: immutable سرو کنید (روش بخش ۷.۱۲).
هشدار: فقط فایل‌های قابل کنترل و قابل اعتماد را با این روش جاسازی کنید. هرگز فایل‌های آپلودشده توسط کاربر را inline نکنید زیرا template.CSS و template.JS سیستم ایمن‌سازی خودکار را دور می‌زنند. این روش فقط برای فایل‌های استاتیک داخل embed.FS که در زمان کامپایل جاسازی شده‌اند، امن است.

7.13.5 شمول فایل در قالب‌ها

یکی از کاربردهای مهم {{ template }} شمول فایل‌های جزئی است. مثلاً یک صفحه ممکن است شامل چندین کامپوننت مشترک باشد. هر کامپوننت در فایل جداگانه تعریف شده و با {{ template }} فراخوانی می‌شود. این الگو امکان استفاده مجدد از اجزای رابط کاربری را فراهم می‌کند:

7.13.6 درخت شمول فایل‌های قالب

هر صفحه‌ی HTML در Go از ترکیب چندین فایل قالب ساخته می‌شود. قالب پایه (base.html) بلوک‌های اصلی را تعریف و قالب‌های جزئی را با {{ template }} فراخوانی می‌کند. هر قالب جزئی ممکن است خود قالب‌های دیگری را فراخوانی کند و یک درخت شمول (inclusion tree) تشکیل شود.

درک این درخت برای دیباگ و سازمان‌دهی قالب‌ها ضروری است. مهم‌ترین نکته این است که تمام فایل‌های قالب باید با هم بارگذاری شوند — مثلاً با ParseGlob یا ParseFS — تا تعاریف {{ define }} همه فایل‌ها در دسترس باشد.

ترتیب بارگذاری فایل‌ها مهم نیست، اما ترتیب رندر مهم است: همیشه باید ExecuteTemplate با نام قالب پایه فراخوانی شود.

7.13.7 سناریوهای عملیاتی

  • سازمان‌دهی ساختار صفحات پیچیده: در پروژه‌های بزرگ، هر صفحه ممکن است ده‌ها قالب جزئی داشته باشد. قالب‌ها را بر اساس عملکرد تفکیک کنید: layouts/ برای قالب‌های پایه، pages/ برای محتوای صفحات، partials/ برای اجزای مشترک و components/ برای ویجت‌های قابل استفاده مجدد. با ParseFS تمام فایل‌ها یکجا بارگذاری می‌شوند.
  • شمول شرطی قالب‌ها: با {{ if .ShowSidebar }}{{ template "sidebar" . }}{{ end }} می‌توانید شمول قالب‌ها را شرطی کنید. این الگو مشابه @if در Blade است و امکان کنترل پویای ساختار صفحه را فراهم می‌کند.
  • توابع کمکی و ابزارهای قالب: با template.FuncMap توابع سفارشی مثل فرمت تاریخ، تبدیل واحد پول و برش متن تعریف کنید. این توابع در تمام قالب‌ها قابل استفاده هستند و مشابه Blade directives در PHP عمل می‌کنند.
  • مدیریت مجموعه‌های بزرگ قالب: در پروژه‌هایی با صدها قالب، از template.New("").Funcs(funcs).ParseFS(fs, patterns...) استفاده کنید تا تمام قالب‌ها با توابع سفارشی یکجا بارگذاری شوند. از بارگذاری تکی فایل‌ها در هر درخواست خودداری کنید چون عملکرد را شدیداً کاهش می‌دهد.
  • پیش‌کامپایل قالب‌ها در زمان راه‌اندازی: تمام قالب‌ها را در تابع init() یا در ابتدای main() بارگذاری و کامپایل کنید تا در صورت خطای قالب، برنامه در همان ابتدا متوقف شود. این الگو (parse once, execute many) را در بخش ۷.۱۱ با جزئیات کامل دیدید.
مهم: همیشه تمام قالب‌ها را یکجا با ParseGlob یا ParseFS بارگذاری کنید و با ExecuteTemplate و نام قالب پایه رندر کنید (نه نام قالب محتوا). هرگز قالب‌های تکی را در هر درخواست Parse نکنید. الگوی کامل پیش‌کامپایل و رندر با ExecuteTemplate در بخش‌های ۷.۹ و ۷.۱۱ توضیح داده شده است.
خلاصه‌ی نکات کلیدی:
  • template با template و define برای include
  • block برای override در child template
  • partial برای قطعات قابل reuse
  • ParseFS برای load از embed
  • بهینه‌سازی با pre-parse در init
