خواندن داده‌های ورودی از request

چکیده: این بخش خواندن ورودی درخواست HTTP را پوشش می‌دهد: query، form، JSON و file upload. الگوی validation و bind to struct بررسی می‌شود. تفاوت با $_GET، $_POST و Request در PHP مشخص می‌گردد.

در برنامه‌های وب دریافت و پردازش داده‌های ارسالی توسط کلاینت نقش بسیار مهمی دارد. این داده‌ها ممکن است به شکل Path params، Query params یا Request Body باشند. در این بخش نحوه خواندن و مدیریت هرکدام را به صورت دقیق و کاربردی توضیح می‌دهیم.

7.3.1 خواندن Query Parameters

پارامترهای کوئری در URL بعد از علامت ? قرار می‌گیرند و معمولا برای فیلتر، صفحه‌بندی، یا جستجو استفاده می‌شوند.

در آدرس زیر:

http://localhost:8080/search?query=golang&page=2

پارامترهای کوئری query و page هستند.

دریافت مقدار پارامتر query و دریافت مقدار صفحه (اختیاری):

r.URL.Query() یک url.Values برمی‌گرداند که شبیه map[string][]string است.

از متد Get برای گرفتن اولین مقدار هر کلید استفاده می‌کنیم.

باید اعتبارسنجی پارامترها را به‌دقت انجام دهید و در صورت نیاز مقدار پیش‌فرض یا خطا برگردانید.

7.3.2 خواندن Path Parameters

از Go 1.22+ به بعد، ServeMux به صورت توکار از پارامترهای مسیر پشتیبانی می‌کند (به بخش ۷.۲ مراجعه کنید). کافیست الگوی مسیر را با {name} ثبت کنید و مقدار را با r.PathValue("name") بخوانید:

در نظر بگیرید URL هایی به شکل زیر داریم:

/user/123

که 123 شناسه کاربر است.

اگر هنوز روی نسخه‌ی قدیمی‌تر از Go 1.22 هستید یا کنترل دستی می‌خواهید، می‌توان با strings.TrimPrefix روی r.URL.Path پارامتر را استخراج کرد؛ اما این روش با افزایش تعداد مسیرها به‌سرعت غیرقابل نگهداری می‌شود.

یادداشت: r.PathValue() در صورت نبود پارامتر رشته‌ی خالی برمی‌گرداند، بنابراین همیشه مقدار را اعتبارسنجی کنید. برای اعتبارسنجی فرمت (مثلاً فقط عدد)، از strconv.Atoi یا regexp استفاده کنید و در صورت خطا کد 400 Bad Request برگردانید. هرگز مقدار خام پارامتر مسیر را مستقیماً به کوئری دیتابیس ندهید.

7.3.3 خواندن داده‌های Request Body

داده‌هایی که در درخواست POST، PUT، PATCH ارسال می‌شوند معمولا در بخش Body قرار دارند. این داده‌ها می‌توانند فرمت‌های مختلفی مثل JSON، فرم‌های HTML (urlencoded) یا فایل باشند.

برای خواندن JSON ابتدا باید Body را بخوانید و سپس آن را به ساختار Go دیکد کنید.

محدود کردن اندازه خواندن به 1MB برای امنیت بیشتر و بررسی وجود مقادیر لازم:

خواندن داده‌های form-data یا urlencoded — برای داده‌های ارسالی توسط فرم‌های HTML که معمولا application/x-www-form-urlencoded یا multipart/form-data هستند، از متد ParseForm یا ParseMultipartForm استفاده می‌کنیم.

7.3.4 نکات امنیتی و بهینه‌سازی هنگام خواندن داده‌های ورودی

محدود کردن اندازه ورودی : همیشه http.MaxBytesReader را برای محدود کردن حجم داده ورودی به کار ببرید تا از حملات DOS جلوگیری شود.

بررسی خطاهای دیکدینگ : حتما خطاهای دیکد JSON یا خواندن فرم را بررسی کنید و پیام خطای مناسب برگردانید.

عدم اعتماد به داده ورودی : هر داده ورودی باید اعتبارسنجی شود، از جمله طول رشته‌ها، نوع داده‌ها، الگوهای خاص و...

جلوگیری از حملات injection : هنگام استفاده از داده‌های ورودی در کوئری‌های دیتابیس یا نمایش در HTML، حتما از روش‌های مناسب پاکسازی و Escaping استفاده کنید.

استفاده از Context : برای زمان‌سنجی یا انصراف عملیات، می‌توانید از r.Context() استفاده کنید.

7.3.5 داخلی‌های پارس درخواست

درک نحوه پارس داده‌ها در Go تفاوت مهمی با PHP دارد. در PHP سوپرگلوبال‌هایی مثل $_GET و $_POST به صورت خودکار پر می‌شوند. اما در Go پارس کردن داده‌ها lazy است:

فراخوانی r.URL.Query() همیشه در دسترس است و نیاز به پارس اضافی ندارد، زیرا query string در زمان پارس URL استخراج می‌شود.

فراخوانی r.ParseForm() داده‌های body را می‌خواند و در r.Form (ترکیب query + body) و r.PostForm (فقط body) ذخیره می‌کند. این متد فقط برای application/x-www-form-urlencoded کار می‌کند.

فراخوانی r.ParseMultipartForm(maxMemory) فرم‌های multipart/form-data را پارس می‌کند. بخش‌های غیرفایلی در حافظه و فایل‌ها در یک دایرکتوری موقت ذخیره می‌شوند. اگر حجم فرم از maxMemory بیشتر شود، مابقی در دیسک نوشته می‌شود.

r.FormValue("key") به صورت ضمنی ParseForm را فراخوانی می‌کند، اما خطای احتمالی را نادیده می‌گیرد. برای کنترل دقیق، ابتدا ParseForm را صریحاً فراخوانی کنید.

هشدار: برخلاف PHP که $_POST فقط داده‌های body را شامل می‌شود، r.FormValue() ابتدا در query string و سپس در body جستجو می‌کند. این رفتار می‌تواند غیرمنتظره باشد. اگر فقط به داده‌های body نیاز دارید، از r.PostFormValue() استفاده کنید.

7.3.9 مقایسه روش‌های پارس ورودی درخواست

یکی از مهم‌ترین تفاوت‌های بنیادین بین PHP و Go در نحوه دسترسی به داده‌های ورودی درخواست است. در PHP سوپرگلوبال‌هایی مثل $_GET و $_POST به صورت خودکار توسط موتور PHP پر می‌شوند و توسعه‌دهنده نیازی به فراخوانی صریح ندارد.

اما در Go هر نوع داده ورودی با متد و رویکرد متفاوتی استخراج می‌شود و توسعه‌دهنده باید بداند کدام متد را برای کدام هدف استفاده کند.

این تفاوت در عمل مزیت محسوب می‌شود زیرا کنترل دقیق‌تری روی منبع داده و نحوه پردازش آن به شما می‌دهد، اما نیازمند آشنایی کامل با هر متد و رفتار آن است. در نمودار زیر می‌توانید شش روش اصلی استخراج داده از درخواست HTTP در Go را همراه با معادل PHP آن‌ها مشاهده کنید:

در جدول بالا شش روش اصلی استخراج داده از درخواست HTTP نمایش داده شده است. هر روش منبع داده خاص خود را دارد و رفتار متفاوتی از خود نشان می‌دهد. برای مثال r.FormValue() برخلاف $_POST در PHP ابتدا در پارامترهای کوئری جستجو می‌کند و سپس در بدنه درخواست، که می‌تواند رفتار غیرمنتظره‌ای ایجاد کند.

همچنین r.PathValue() که در Go 1.22 اضافه شده، امکان تعریف پارامترهای مسیر را بدون نیاز به فریم‌ورک خارجی فراهم می‌کند. درک این تفاوت‌ها برای مهاجرت صحیح از PHP به Go حیاتی است و از باگ‌های امنیتی جلوگیری می‌کند.

7.3.10 سناریوهای عملیاتی خواندن ورودی درخواست

در پروژه‌های واقعی با انواع مختلفی از درخواست‌ها روبرو می‌شوید که هر کدام نیازمند رویکرد متفاوتی برای خواندن و اعتبارسنجی داده‌ها هستند. شناخت مناسب سناریوهای عملیاتی به شما کمک می‌کند تا برای هر موقعیت بهترین روش پارس را انتخاب کنید و از خطاهای رایج جلوگیری کنید. در ادامه پنج سناریوی عملیاتی پرتکرار را بررسی می‌کنیم:

  • پارس بدنه درخواست JSON API: هنگام ساخت API های REST، کلاینت‌ها معمولاً داده‌ها را به صورت JSON در بدنه درخواست ارسال می‌کنند. در این حالت باید ابتدا هدر Content-Type: application/json را بررسی کنید، سپس با json.NewDecoder(r.Body) داده را دیکد کنید. حتماً از http.MaxBytesReader برای محدودیت حجم و DisallowUnknownFields() برای جلوگیری از فیلدهای ناشناخته استفاده نمایید. این رویکرد بسیار ایمن‌تر از PHP است که در آن json_decode(file_get_contents('php://input')) بدون هیچ محدودیت حجمی انجام می‌شود.
  • مدیریت ارسال فرم‌های HTML: فرم‌های سنتی HTML داده‌ها را با application/x-www-form-urlencoded یا multipart/form-data ارسال می‌کنند. برای حالت اول از r.ParseForm() و سپس r.PostFormValue() استفاده کنید. دقت کنید که r.FormValue() مقادیر کوئری را هم شامل می‌شود، بنابراین اگر فقط به داده‌های بدنه نیاز دارید از r.PostFormValue() استفاده نمایید تا از تداخل با پارامترهای URL جلوگیری شود.
  • پردازش آپلود فایل: برای دریافت فایل آپلودشده ابتدا r.ParseMultipartForm(maxMemory) را فراخوانی کنید، سپس با r.FormFile("fieldname") به فایل دسترسی پیدا کنید. حتماً نوع واقعی فایل را با http.DetectContentType() بررسی کنید و هرگز به پسوند فایل اعتماد نکنید. نام فایل ذخیره‌شده را با ترکیب زمان و UUID تولید کنید تا از حملات مسیر فایل جلوگیری شود.
  • اعتبارسنجی پارامترهای کوئری: پارامترهای کوئری معمولاً برای فیلتر، صفحه‌بندی و جستجو استفاده می‌شوند. همیشه مقادیر پیش‌فرض تعیین کنید، اعداد را با strconv.Atoi() تبدیل و محدوده آن‌ها را بررسی کنید. از r.URL.Query() به جای r.FormValue() استفاده کنید تا فقط مقادیر کوئری خوانده شود و خطر تداخل با داده‌های بدنه وجود نداشته باشد.
  • استراتژی پارس بر اساس Content-Type: بهترین روش مدیریت درخواست‌ها، بررسی هدر Content-Type قبل از هر عملیاتی است. اگر application/json باشد از json.NewDecoder، اگر application/x-www-form-urlencoded باشد از r.ParseForm، و اگر multipart/form-data باشد از r.ParseMultipartForm استفاده کنید. این استراتژی از خطاهای پارس و حفره‌های امنیتی جلوگیری می‌کند.
نکته کاربردی: همیشه هدر Content-Type را قبل از پارس کردن بررسی کنید. بسیاری از باگ‌های امنیتی از این ناشی می‌شوند که سرور فرض می‌کند درخواست JSON است اما کلاینت داده فرم ارسال کرده. اگر بدون بررسی Content-Type سعی کنید JSON را از یک فرم multipart/form-data پارس کنید، نه‌تنها خطای دیکد دریافت می‌کنید بلکه ممکن است r.Body قبلاً توسط ParseMultipartForm خوانده شده و دیگر قابل دسترسی نباشد. الگوی ایمن این است که ابتدا Content-Type را بررسی و سپس متد پارس مناسب را انتخاب کنید.
