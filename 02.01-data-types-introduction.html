آشنایی با انواع داده

چکیده: این بخش سیستم نوع‌دهی Go را از پایه باز می‌کند: انواع اولیه، مقادیر صفر، ساختار داخلی رشته‌ها و انواع مرکب. تفاوت array با slice، رفتار map و struct با مثال‌های عملی توضیح داده می‌شود. درک string header و immutable بودن رشته‌ها برای کدنویسی کارآمد ضروری است.

ساختار داده یکی از بنیادی‌ترین مفاهیم در علوم کامپیوتر است که ابزار اصلی برای نمایش مفاهیم ذخیره‌سازی اطلاعات و کنترل منطق برنامه محسوب می‌شود.

در زبان‌های پویا مانند PHP سیستم نوع‌دهی بر پایه Dynamic Typing عمل می‌کند به این معنا که نوع متغیرها در زمان اجرا تعیین می‌شود و برنامه‌نویس نیازی به تعریف صریح نوع آن‌ها ندارد.

این ویژگی سادگی و سرعت توسعه را افزایش می‌دهد اما در عین حال می‌تواند منجر به بروز خطاهایی شود که تنها در زمان اجرا آشکار می‌شوند.

از سویی زبان Go با بهره‌گیری از Static Typing و طراحی دقیق و سخت‌گیرانه‌اش برنامه‌نویس را ملزم می‌کند که پیش از استفاده از هر متغیر نوع آن را به‌طور صریح مشخص کند. این رویکرد باعث می‌شود بسیاری از خطاها در همان مرحله‌ی کامپایل شناسایی شوند و کیفیت و پایداری کد به‌طور قابل‌توجهی افزایش یابد.

این تفاوت بنیادین در فلسفه‌ی نوع‌دهی اهمیت درک عمیق و صحیح انواع داده‌ای Primitive مانند اعداد، رشته‌ها و مقادیر بولی و Composite مانند آرایه‌ها، slice‌ها، struct‌ها و map را در Go دوچندان می‌کند. بدون درک درست از این مفاهیم نوشتن کدی مؤثر، مقیاس‌پذیر و کم‌خطا دشوار خواهد بود.

در این فصل با رویکردی مقایسه‌ای سیستم نوع‌دهی Go را بررسی می‌کنیم و تفاوت آن با PHP آشکار می‌سازیم و می‌آموزیم چگونه می‌توان به‌صورت عملی با انواع داده‌ای مختلف در Go کار کرد و از قابلیت‌های آن برای تولید نرم‌افزارهای قدرتمند و پایدار بهره گرفت.

نسبت زمان صرف‌شده برای خواندن کد به نوشتن آن به‌وضوح بیش از ۱۰ به ۱ است. خوانا کردن کد، نوشتن آن را آسان‌تر می‌کند.

نکته‌ی حرفه‌ای: سیستم نوع‌دهی صریح Go در کدبیس‌های بزرگ یک مزیت رقابتی است. در PHP با رشد پروژه، عدم قطعیت نوع متغیرها باعث می‌شود هر فراخوانی تابع نیازمند بررسی مستندات یا کد منبع باشد. اما در Go امضای تابع func Process(order Order, repo Repository) error فوراً می‌گوید چه ورودی‌هایی لازم است و چه خروجی‌ای ممکن است. همین صراحت، زمان درک کد را کاهش و اطمینان از صحت تغییرات را افزایش می‌دهد — به‌ویژه وقتی ده‌ها توسعه‌دهنده روی یک پروژه کار می‌کنند.

2.1.1 انواع اولیه

Integer — در PHP تعریف یک عدد صحیح بسیار ساده است و نوع آن به‌صورت دینامیک در زمان اجرا تعیین می‌شود:

در Go نوع متغیرها ایستا و صریح است و باید نوع آن مشخص شود. دو روش برای تعریف آن وجود دارد:

Go از چندین نوع عدد صحیح با اندازه‌های مختلف پشتیبانی می‌کند:

int : نوع پیش‌فرض و وابسته به معماری سیستم که معمولاً 32 یا 64 بیت است

Go برخلاف PHP از تبدیل خودکار نوع بین int و int64 جلوگیری می‌کند. این سخت‌گیری مانع بروز خطاهای پنهان می‌شود.

طراحی حافظه‌ی انواع عددی در Go: هر نوع عددی اندازه‌ی دقیق و مشخصی در حافظه دارد. int8 دقیقاً ۱ بایت، int16 دو بایت، int32 چهار بایت و int64 هشت بایت اشغال می‌کند. نوع int و uint بسته به معماری پردازنده (۳۲ یا ۶۴ بیتی) اندازه متفاوتی دارند. در سیستم‌های ۶۴ بیتی int معادل int64 است. نوع uintptr نیز برای نگهداری مقدار عددی یک اشاره‌گر استفاده می‌شود و اندازه‌اش با اندازه‌ی اشاره‌گر سیستم برابر است. برخلاف PHP که هر عدد صحیح را در ساختار zval با ۱۶ بایت ذخیره می‌کند، Go فقط به اندازه‌ی لازم حافظه مصرف می‌کند.

Floating-point — در PHP تعریف یک عدد اعشاری ساده است و نوع آن به‌صورت دینامیک تعیین می‌شود:

در Go نوع متغیرها صریح و ایستا است و باید نوع عدد اعشاری مشخص شود:

  • float32 : دقت پایین‌تر و حافظه کمتر (حدود ۷ رقم دقت)
  • float64 : دقت بالاتر و پیش‌فرض برای اعداد اعشاری (حدود ۱۵ رقم دقت)

Go به دقت محاسبات عددی توجه ویژه دارد و بین float32 و float64 تفاوت جدی قائل می‌شود. انتخاب نوع مناسب برای محاسبات حساس به دقت مانند محاسبات علمی یا مالی اهمیت زیادی دارد.

هشدار درباره‌ی دقت اعشاری: نوع float32 فقط حدود ۷ رقم دقت اعشاری دارد و float64 حدود ۱۵ رقم. برای محاسبات مالی هرگز از float استفاده نکنید — از کتابخانه‌هایی مانند shopspring/decimal یا نوع سفارشی مبتنی بر int64 (ذخیره‌ی مبلغ به‌صورت سِنت) استفاده کنید. در PHP نیز مشکل مشابهی وجود دارد اما به‌دلیل dynamic typing کمتر به‌چشم می‌آید.

فیلد Data اشاره‌گری به آرایه‌ای از بایت‌های فقط‌خواندنی است و Len تعداد بایت‌ها را نگه می‌دارد. به همین دلیل است که رشته‌ها immutable هستند — داده‌ی زیربنایی در حافظه‌ی فقط‌خواندنی قرار دارد و هنگام تغییر، یک آرایه‌ی جدید ساخته می‌شود. انتساب رشته فقط کپی ۱۶ بایتِ header است نه خود داده. این مکانیزم شبیه به Copy-on-Write در PHP است اما تفاوت مهمی دارد: در PHP رشته‌ها هنگام تغییر واقعاً کپی می‌شوند (به‌دلیل reference counting) اما در Go چندین رشته می‌توانند به همان بایت‌های زیربنایی اشاره کنند تا زمانی که تغییری نیاز نباشد.

Pointer — در PHP هیچ نوع صریحی از اشاره‌گر وجود ندارد. در Go اشاره‌گرها بخشی طبیعی از زبان هستند. در بخش های بعد مفهوم اشاره‌گر و کاربردهای آن به صورت مفصل تشریح خواهد شد.

2.1.2 انواع مرکب

Array — آرایه‌ها در Go ساختارهایی با اندازه ثابت و نوع مشخص هستند که مجموعه‌ای از مقادیر هم‌نوع را در خود نگه می‌دارند. برخلاف PHP که آرایه‌ها می‌توانند اندازه متغیر و انواع مختلف داده را در خود جای دهند آرایه‌های Go بسیار سخت‌گیرانه‌تر و ایستا هستند.

آرایه‌ها در Go اندازه‌ی ثابت دارند و بخشی از نوع آن‌ها است.

تفاوت‌های کلیدی آرایه‌ها در Go نسبت به PHP — اندازه ثابت: در Go طول آرایه بخشی از نوع آن است. برای نمونه، [3]int و [4]int دو نوع کاملاً متفاوت به حساب می‌آیند و نمی‌توان آن‌ها را با هم جایگزین کرد یا آیتمی از آن را حذف کرد. نوع ایستا: برعکس PHP همه اعضای آرایه باید از یک نوع مشخص باشند مثلاً int یا string.

مقادیر پیش‌فرض اگر آرایه‌ای تعریف شود ولی مقداردهی نشود به صورت خودکار با zero value آن نوع داده پر می‌شود مثلاً zero value نوع int عدد صفر است.

با توجه به نکات ذکر شده اگر نیاز باشد در زمان اجرا مقادیر یک آرایه به روزرسانی شود به روش زیر عمل میکنیم:

نکته‌ی حرفه‌ای — array یا slice؟ در PHP تنها یک ساختار آرایه دارید، اما در Go انتخاب بین array و slice عمدی است. از array فقط وقتی استفاده کنید که طول ثابت در زمان کامپایل معنای دامنه‌ای دارد (مثلاً آدرس IPv4 به‌صورت [4]byte یا ماتریس [3][3]float64)؛ در غیر این صورت slice انتخاب idiomatic است. آرایه‌ها با انتساب کامل کپی می‌شوند و این رفتار برای برنامه‌نویسان PHP غیرمنتظره است.

Slice — slice از ویژگی‌های مهم Go است و تقریباً جایگزین آرایه‌های دینامیک در PHP محسوب می‌شود. آرایه‌ها در Go طول ثابتی دارند و به‌ندرت به‌صورت روزمره استفاده می‌شوند. به جای آن Go ساختاری به نام Slice ارائه کرده که قدرت و انعطاف‌پذیری آرایه‌های PHP را با امنیت و کارایی بیشتر فراهم می‌کند.

در پشت صحنه یک slice به یک آرایه‌ی واقعی اشاره می‌کند و فقط بخش مشخصی از آن را نمایان می‌سازد.

تغییر در مقادیر slice می‌تواند آرایه‌ی زیربنایی را نیز تغییر دهد.

Len تعداد عناصری است که slice در حال حاضر شامل می‌شود و Cap ظرفیت کل آرایه‌ی زیربنایی از نقطه‌ی شروع Data به بعد را نشان می‌دهد. انتساب یک slice به متغیر دیگر فقط این ۲۴ بایت header را کپی می‌کند نه داده‌ها را — به همین دلیل دو slice می‌توانند به همان آرایه‌ی زیربنایی اشتراک داشته باشند. این رفتار با Copy-on-Write در آرایه‌های PHP تفاوت بنیادین دارد: در PHP وقتی $b = $a می‌نویسید ابتدا داده‌ها به‌اشتراک گذاشته می‌شوند اما به‌محض تغییر یکی از آن‌ها کپی ایجاد می‌شود. اما در Go داده‌ها واقعاً مشترک می‌مانند مگر اینکه append باعث ایجاد آرایه‌ی جدید شود.

ساختار داخلی Map در Go: Map در Go با استفاده از Hash Table پیاده‌سازی شده است. هر map از چندین bucket تشکیل شده و هر bucket می‌تواند ۸ جفت کلید-مقدار را ذخیره کند. وقتی bucket پر شود، bucket overflow bucket جدیدی به آن زنجیره می‌شود. فرآیند هش کردن از یک hash seed تصادفی استفاده می‌کند که در زمان ایجاد map تولید می‌شود — این مکانیزم از حملات Hash DoS جلوگیری می‌کند (حملتی که در PHP نیز با محدودیت تعداد کلیدهای ورودی کنترل می‌شود). وقتی تعداد عناصر از آستانه‌ی بارگذاری (load factor ≈ 6.5) فراتر رود، Go آرایه‌ی bucketها را دو برابر کرده و عناصر را rehash می‌کند. برخلاف PHP که آرایه‌ها مرتب‌ هستند و ترتیب درج را حفظ می‌کنند، map در Go ترتیب تضمینی ندارد و پیمایش آن در هر بار ممکن است ترتیب متفاوتی داشته باشد.

Struct — در زبان Go مفهومی به نام کلاس وجود ندارد اما به‌جای آن ساختار داده‌ای به نام struct برای تعریف داده‌های ترکیبی و سازمان‌دهی اطلاعات استفاده می‌شود. Structها مانند جعبه‌هایی هستند که می‌توانند چندین مقدار با انواع مختلف را در خود جای دهند. یکی از تفاوت‌های مهم Go با PHP این است که در Go ارث‌بری وجود ندارد.

به جای آن می‌توان Composition انجام داد یعنی یک struct می‌تواند شامل struct دیگری به صورت embedding باشد که باعث قابلیت استفاده مجدد و سازماندهی بهتر کد می‌شود که این موارد در فصل های بعد در بخش مربوط به شی‌گرایی بیشتر توضیح داده خواهد شد.

در PHP می‌توان ثابت‌ها را با define یا const تعریف کرد اما تفاوتی مهم در Go این است که ثابت‌ها واقعاً compile-time constant هستند نه فقط مقادیر تغییر ناپذیر نوع const می‌تواند صریح یا مبهم باشد. Go تا زمانی که لازم نباشد نوع دقیقی به const اختصاص نمی‌دهد.

با کمک iota می‌توانید به راحتی Enum های مشابه PHP را تعریف کنید. الگوهای iota و custom type ضمن ساده‌سازی کد موجب افزایش خوانایی و نگهداری آسان‌تر برنامه‌های Go می‌شوند و تفاوت اصلی Go با زبان‌های شیءگرای سنتی را نشان می‌دهند.

2.1.3 دامنه‌ی متغیرها

دامنه یا Scope تعیین می‌کند که یک متغیر در کدام بخش از برنامه قابل دسترسی است. در زبان Go نحوه‌ی تعریف متغیر نقش مهمی در تعیین محدوده‌ی آن دارد

متغیرهای تعریف‌شده با =: — این نوع تعریف معمولاً در داخل توابع استفاده می‌شود و دامنه‌ی آن تنها به همان Block محدود است. به بیان دیگر چنین متغیری فقط در همان محدوده‌ای که تعریف شده قابل استفاده خواهد بود و بیرون از آن شناخته‌شده نیست.

متغیرهای تعریف‌شده با var — اگر در سطح پکیج تعریف شوند در سراسر فایل و حتی در کل پکیج در دسترس خواهند بود. این موضوع امکان تعریف متغیرهایی را فراهم می‌کند که در بخش‌های مختلف کد قابل استفاده باشند.

حروف بزرگ و کوچک در نام‌گذاری متغیرها — یکی از ویژگی‌های خاص Go این است که دسترسی به متغیرها و به طور کلی شناسه‌ها به حرف اول نام آن‌ها بستگی دارد. اگر نام یک متغیر با حرف بزرگ شروع شود مانند Name آن متغیر Export شده محسوب می‌شود و از پکیج‌های دیگر نیز قابل دسترسی خواهد بود.

اما اگر نام با حرف کوچک شروع شود مانند name تنها در همان پکیج فعلی معتبر خواهد بود.

جزئیات کامل این مفهوم در فصل شی‌گرایی نیز بررسی خواهد شد.

این شیوه‌ی مدیریت دامنه‌ی متغیرها باعث می‌شود :

1. از تداخل نام‌ها در بخش‌های مختلف برنامه جلوگیری شود.

2. کدی ساخت‌یافته‌تر، خواناتر و قابل نگهداری‌تر تولید گردد.

3. توسعه‌دهنده بتواند به‌طور آگاهانه مشخص کند که هر متغیر در چه سطحی از برنامه قابل مشاهده باشد.

مقایسه‌ی ساختار zval در PHP با انواع داده در Go:

در PHP هر متغیر در ساختاری به نام zval ذخیره می‌شود که شامل نوع داده، مقدار و اطلاعات reference counting است. ساختار zval حدود ۱۶ بایت حافظه مصرف می‌کند — مهم نیست مقدار داخلی چه باشد. بنابراین یک bool در PHP همان مقدار حافظه‌ی یک int مصرف می‌کند.

در Go هر نوع داده به‌طور دقیق به اندازه‌ی واقعی خود حافظه مصرف می‌کند: bool فقط ۱ بایت، int32 چهار بایت و int64 هشت بایت. هیچ overhead اضافی برای type tag یا reference counting وجود ندارد. اطلاعات نوع فقط در زمان کامپایل استفاده می‌شود و در زمان اجرا حافظه‌ای اشغال نمی‌کند (مگر برای انواعی که از interface استفاده می‌کنند).

علاوه بر این، PHP برای مدیریت حافظه از reference counting و garbage collector استفاده می‌کند. هر zval شامل شمارنده‌ای است که تعداد ارجاع‌ها را رهگیری می‌کند. Go از روش متفاوتی استفاده می‌کند: garbage collector مبتنی بر تری‌کالر mark-and-sweep که هیچ نیازی به reference counting ندارد و overhead کمتری در زمان اجرا دارد.

2.1.4 تفاوت بنیادین با nil در PHP

مقدار صفر را مفید کنید. مقدار صفر یک نوع باید بدون مقداردهی اولیه صریح آماده استفاده باشد. این اصل طراحی در Go است که دسته‌های کاملی از باگ‌های مرتبط با داده‌های مقداردهی‌نشده را حذف می‌کند.

از تفاوت‌های فلسفی مهم بین Go و PHP در نحوه‌ی برخورد با متغیرهای مقداردهی‌نشده است. در PHP متغیری که مقداردهی نشده باشد null است — یعنی «مقداری ندارد». اما در Go هر نوع داده‌ای یک zero value دارد که هنگام تعریف متغیر بدون مقداردهی صریح، به‌طور خودکار به آن اختصاص می‌یابد. این یعنی در Go هیچ متغیری هرگز «بدون مقدار» نیست.

2.1.5 نوع‌مستعار در برابر نوع‌جدید

Go دو روش متفاوت برای تعریف انواع سفارشی ارائه می‌دهد که رفتار کاملاً متفاوتی دارند. این تفاوت برای برنامه‌نویسان PHP که با type alias آشنا نیستند بسیار مهم است و درک آن از خطاهای عجیب کامپایلر جلوگیری می‌کند.

چه زمانی از کدام استفاده کنیم؟ از Type Definition (type Score int) وقتی استفاده کنید که می‌خواهید نوعی با هویت مستقل بسازید که نتوان آن را به‌اشتباه با نوع پایه جایگزین کرد — مثلاً Score نباید با UserID جمع شود. از Type Alias (type MyInt = int) فقط در موارد خاص مثل بازسازی پکیج یا سازگاری با کد قدیمی استفاده کنید. در کد معمولی، Type Definition رایج‌تر و ایمن‌تر است.

2.1.6 رفتار Overflow در انواع عددی

در PHP اعداد صحیح وقتی از حد مجاز فراتر روند به‌طور خودکار به float تبدیل می‌شوند. اما در Go انواع عددی سرریز خاموش (silent overflow) دارند: مقدار بدون خطا از سرریز می‌شود و به مقدار اشتباهی تبدیل می‌گردد بدون اینکه خطایی داده شود. این رفتار عمدی است برای کارایی بالا، اما می‌تواند منبع باگ‌های خطرناک باشد.

توصیه‌ی عملی: اگر با اعداد ورودی کاربر یا مقادیر دیتابیس کار می‌کنید، حتماً بازه‌ی مجاز را بررسی کنید. برای کارهای حساس (مثلاً محاسبات مالی) از بسته‌ی math/big یا کتابخانه‌های تخصصی استفاده کنید. هرگز به سرریز نشدن اعداد اعتماد نکنید.

2.1.7 الگوهای پیشرفته‌ی iota

همان‌طور که در بخش ثابت‌ها اشاره شد، Go از iota به‌عنوان شمارنده‌ی خودکار در بلوک‌های const استفاده می‌کند. در ادامه الگوهای قدرتمندتری را بررسی می‌کنیم که در PHP معادل مستقیمی ندارند و باید مقادیر را دستی بنویسید.

نکته‌ی فنی: ثابت‌ها در Go می‌توانند بسیار بزرگ‌تر از انواع عددی معمولی باشند چون در زمان کامپایل ارزیابی می‌شوند و محدودیت حافظه‌ی زمان‌اجرا ندارند. مثلاً const huge = 1e1000 در Go معتبر است اما فقط در عبارات ثابت قابل استفاده است و نمی‌توان آن را به متغیر float64 اختصاص داد.

2.1.8 هزینه‌ی تبدیل string به []byte

تبدیل بین string و []byte یکی از رایج‌ترین عملیات در برنامه‌های Go است اما هزینه‌ی پنهانی دارد: هر تبدیل یک کپی کامل از داده ایجاد می‌کند. برای رشته‌های کوچک این مسئله مهم نیست اما وقتی با داده‌های بزرگ (مثلاً خواندن فایل) کار می‌کنید، کپی‌های مکرر می‌توانند کارایی را به‌شدت کاهش دهند.

بهینه‌سازی پیشرفته: در مسیرهای بحرانی کد می‌توانید از unsafe.Pointer برای تبدیل بدون کپی استفاده کنید (که در بخش ۲.۲ توضیح داده شده). اما این روش فقط وقتی امن است که []byte پس از تبدیل تغییر نکند. اگر داده‌ی بزرگ را فقط می‌خوانید، این بهینه‌سازی می‌تواند تأثیر قابل‌توجهی داشته باشد.

2.1.9 مقایسه‌ی ساختار حافظه

یکی از تفاوت‌های بنیادین PHP و Go در نحوه‌ی ذخیره‌سازی مقادیر در حافظه نهفته است. در PHP هر متغیر فارغ از نوع داده‌ی آن در یک ساختار یکسان به نام zval نگهداری می‌شود که شامل برچسب نوع، مقدار واقعی، شمارنده‌ی ارجاع و پرچم ارجاع است.

این طراحی یکنواخت انعطاف‌پذیری بالایی در زمان اجرا فراهم می‌کند اما هزینه‌ی حافظه‌ی قابل‌توجهی دارد.

در مقابل Go هر مقدار دقیقاً به اندازه‌ی نوع واقعی خود فضا اشغال می‌کند بدون هیچ سربار اضافی برای مدیریت نوع در زمان اجرا.

این تفاوت ساختاری پیامدهای عملی مهمی دارد: برنامه‌های Go معمولاً حافظه‌ی بسیار کمتری نسبت به معادل PHP خود مصرف می‌کنند. برای نمونه، ذخیره‌ی هزار عدد صحیح در PHP حدود ۱۶ کیلوبایت فقط برای ساختارهای zval نیاز دارد اما در Go فقط ۸ کیلوبایت.

این بهره‌وری حافظه مستقیماً بر کارایی کش پردازنده و سرعت اجرای برنامه تأثیر می‌گذارد و یکی از دلایل اصلی برتری عملکرد Go در کارهای محاسباتی است.

2.1.10 سناریوهای عملیاتی

انتخاب نوع داده‌ی مناسب در Go تأثیر مستقیمی بر کارایی، خوانایی و ایمنی کد دارد. برخلاف PHP که نوع متغیرها به‌طور خودکار تعیین می‌شود در Go هر تصمیم‌گیری درباره‌ی نوع داده باید آگاهانه و عمدی باشد.

در ادامه سناریوهای عملیاتی رایج را بررسی می‌کنیم که برنامه‌نویسان PHP هنگام انتقال به Go با آن‌ها مواجه می‌شوند و راه‌حل‌های idiomatic برای هر مورد ارائه می‌دهیم.

  • انتخاب نوع عددی مناسب: در PHP همه‌ی اعداد صحیح یک نوع دارند اما در Go باید بین int، int64 و float64 تصمیم بگیرید. از int برای شمارنده‌ها و ایندکس‌ها استفاده کنید. از int64 زمانی که با مقادیر بزرگ مانند شناسه‌های دیتابیس یا timestamp کار می‌کنید بهره ببرید. از float64 برای محاسبات علمی و آماری استفاده کنید اما هرگز برای مبالغ مالی به‌کار نبرید. برای محاسبات مالی از نوع سفارشی مبتنی بر int64 یا کتابخانه‌ی decimal استفاده کنید.
  • تفاوت مدیریت رشته: رشته‌ها در Go تغییرناپذیر و مجموعه‌ای از بایت‌ها هستند نه کاراکتر. برخلاف PHP که رشته‌ها قابل تغییرند و با encoding مختلف کار می‌کنند، در Go رشته همیشه UTF-8 است و هر تغییری رشته‌ی جدیدی ایجاد می‌کند. برای ساخت رشته‌ی بزرگ از strings.Builder به‌جای الحاق مکرر استفاده کنید تا از ایجاد اشیاء موقت زیاد جلوگیری شود.
  • الگوی مقدار صفر: در Go هر نوع بدون مقداردهی صریح مقدار صفر خود را می‌گیرد: int صفر، bool نادرست، string خالی و slice برابر nil. این رفتار عمدی است نه یک خطا. انواع خود را طوری طراحی کنید که مقدار صفر آن‌ها معتبر و ایمن باشد. مثلاً sync.Mutex بدون مقداردهی اولیه قابل استفاده است چون مقدار صفر آن حالت قفل‌نشده دارد.
  • زمان استفاده از const در برابر var: از const برای مقادیری استفاده کنید که در زمان کامپایل معلوم‌اند مانند اندازه‌ی بافر، URL پایه یا تعداد صفحات. از var برای مقادیری که در زمان اجرا تعیین می‌شوند مانند تنظیمات محیطی یا نتایج تابع. ثابت‌ها در Go نمی‌توانند ساختار پیچیده داشته باشند فقط انواع اولیه، رشته و iota.
  • نوع‌دستی برای شفافیت دامنه: با type Score int یا type UserID int64 می‌توانید انواع سفارشی بسازید که خوانایی کد را افزایش می‌دهد و از اشتباه گرفتن مقادیر مختلف جلوگیری می‌کند. کامپایلر Go بین Score و int تفاوت قائل می‌شود و نمی‌توانید ناخواسته یکی را به‌جای دیگری استفاده کنید. این رویکرد در PHP ممکن نیست چون نوع‌دهی پویا چنین امنیتی فراهم نمی‌کند.
مقدار صفر ویژگی است نه مشکل: Go برخلاف PHP مفهوم null همه‌گیر ندارد. هر متغیر بدون مقداردهی مقدار صفر نوع خود را می‌گیرد که همیشه معتبر و ایمن است. انواع struct خود را طوری طراحی کنید که مقدار صفر آن‌ها بلافاصله قابل استفاده باشد. مثلاً به‌جای تابع سازنده‌ای که همه‌ی فیلدها را اجباری می‌کند، فیلدها را با مقادیر پیش‌فرض معتبر طراحی کنید. این الگو در کتابخانه‌ی استاندارد Go به‌طور گسترده استفاده شده: bytes.Buffer، sync.Mutex و http.Server همگی بدون مقداردهی اولیه قابل استفاده‌اند. اگر نوعی نیاز به مقداردهی اجباری دارد تابع NewX() بسازید اما مقدار صفر را بی‌معنی نکنید.
