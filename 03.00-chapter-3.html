فصل ۳

فصل سوم

پکیج‌ها، ماژول‌ها و شی‌گرایی — سه ستون اصلی که کد Go شما را از یک مجموعه‌ی پراکنده‌ی فایل‌ها به یک سیستم منسجم، قابل‌توسعه و قابل‌نگهداری تبدیل می‌کنند. اگر از PHP می‌آیید، احتمالاً با Namespace ها برای سازمان‌دهی کد، Composer برای مدیریت وابستگی‌ها و کلاس‌ها/اینترفیس‌ها برای پیاده‌سازی الگوهای شی‌گرا آشنا هستید. اما در Go هر یک از این مفاهیم با فلسفه‌ای متفاوت و ابزارهایی ساده‌تر اما قدرتمندتر پیاده‌سازی شده‌اند. این فصل شما را از دنیای آشنای PHP به دنیای Idiomatic Go راهنمایی می‌کند.

در این فصل خواننده با مفاهیم زیر آشنا خواهد شد:

  • مفهوم پکیج‌ها در Go و نقش آن‌ها در سازمان‌دهی کد — مقایسه با Namespace ها در PHP و تفاوت‌های بنیادین
  • تعریف و استفاده از پکیج‌ها، شامل پکیج main ، توابع init برای آماده‌سازی اولیه و internal پکیج‌ها برای محدودسازی دسترسی
  • نحوه import کردن پکیج‌ها، استفاده از alias و import با _ برای اجرای توابع init — و جلوگیری از وابستگی دوری
  • مدیریت سطح دسترسی در پکیج‌ها از طریق نام‌گذاری (exported در برابر unexported)
  • مدیریت وابستگی‌ها با استفاده از go.mod و go.sum ، الگوریتم MVS ، و مقایسه عمیق با Composer
  • اجرای برنامه‌ها با go run و ساخت فایل‌های اجرایی با go build شامل کامپایل متقاطع و تزریق نسخه
  • درک چرخه‌ی حیات برنامه در Go شامل مراحل Startup ، Running و Graceful Shutdown
  • مفاهیم شی‌گرایی در Go: struct به‌جای کلاس، Composition به‌جای وراثت، Embedding و کپسوله‌سازی با نام‌گذاری
  • تعریف و استفاده از interface ها در Go با تأکید بر Duck Typing ، پیاده‌سازی ضمنی و ساختار داخلی iface/eface
  • ساخت اشیاء با توابع Factory ، الگوی Functional Options ، Builder و تزریق وابستگی
  • ترکیب interface ها برای ایجاد رفتارهای پیچیده و استفاده از آن‌ها برای mock تست‌پذیری بهتر
چرا این فصل مهم است؟ به‌عنوان یک توسعه‌دهنده PHP، شما با Namespace ها، Composer ، کلاس‌ها و Interface ها آشنا هستید. اما Go این مفاهیم را به شکلی کاملاً متفاوت پیاده‌سازی کرده است. درک تفاوت‌های عمیق بین این دو زبان — از نحوه‌ی حل‌وفصل پکیج‌ها توسط کامپایلر تا الگوریتم MVS در مدیریت وابستگی‌ها، از ساختار داخلی interface ها تا قواعد method set — به شما کمک می‌کند هم کد Go بنویسید و هم Idiomatic Go بنویسید؛ کدی که از فلسفه و طراحی زبان پیروی می‌کند نه صرفاً ترجمه‌ی عادت‌های PHP به Go.
نکته‌ی کلیدی برای مهاجرت: بزرگترین اشتباه توسعه‌دهندگان PHP در Go این است که سعی می‌کنند الگوهای PHP را مستقیماً در Go پیاده‌سازی کنند — مثلاً سلسله‌مراتب عمیق وراثت، getter/setter برای هر فیلد، یا Exception برای هر خطا. این فصل به شما نشان می‌دهد که چگونه ذهنیت خود را از «ترجمه‌ی کد» به «تبدیل الگو» تغییر دهید. Go زبان PHP نیست و این تفاوت نه باگ بلکه طراحی عمدی است.
