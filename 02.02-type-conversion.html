Type Conversion

چکیده: تبدیل نوع در Go همیشه صریح است؛ هیچ Type Juggling مانند PHP وجود ندارد. این بخش strconv، type assertion، type switch و unsafe.Pointer را پوشش می‌دهد. هر روش با مثال و هشدار درباره‌ی خطرات سطح پایین ارائه می‌شود.

در زبان Go برخلاف PHP، تبدیل نوع به صورت صریح انجام می‌شود و کامپایلر به‌هیچ‌وجه به‌طور خودکار مقادیر را بین انواع مختلف تبدیل نمی‌کند.

قاعده‌ی کلی این است که هر زمان بخواهیم مقدار یک متغیر را به نوع دیگری تغییر دهیم، باید نام نوع مقصد را مانند یک تابع فراخوانی کنیم و مقدار مورد نظر را به‌عنوان آرگومان قرار دهیم.

این الزام به صراحت باعث می‌شود کد شفاف‌تر، قابل پیش‌بینی‌تر و عاری از تبدیل‌های پنهان یا ناخواسته باشد.

بسیاری از تبدیل‌های string نیاز به استفاده از پکیج استاندارد strconv دارند. هنگام تبدیل بین انواع عددی با اندازه مختلف مثل int64 به int32 مراقب overflow باشید.

تبدیل نوع در Go در مقابل Type Juggling در PHP:

در PHP عملگرهای ریاضی و مقایسه‌ای به‌صورت خودکار انواع را تبدیل می‌کنند (Type Juggling). مثلاً "3" + 4 بدون خطا نتیجه‌ی 7 می‌دهد و "foo" == 0 مقدار true برمی‌گرداند! این رفتار منبع بسیاری از باگ‌های ناشناخته است.

در Go چنین تبدیل خودکاری وجود ندارد. "3" + 4 خطای کامپایل است. باید صریحاً بنویسید 3 + strconv.Atoi("3") یا strconv.Itoa(3) + "4". این سخت‌گیری در نگاه اول آزاردهنده است اما از دسته‌ای کامل از باگ‌ها جلوگیری می‌کند.

هشدار: استفاده از unsafe کد شما را از گارانتی‌های ایمنی حافظه‌ی Go خارج می‌کند و ممکن است با تغییر نسخه‌ی Go کد شما خراب شود. فقط در شرایط خاص (مثل بهینه‌سازی حافظه‌ی بحرانی) از آن استفاده کنید. در PHP هیچ معادلی برای این سطح دسترسی به حافظه وجود ندارد.

2.2.3 تفاوت Type Assertion و Type Conversion

از رایج‌ترین منابع اشتباه در میان برنامه‌نویسان PHP که به Go مهاجرت می‌کنند، خلط کردن دو مفهوم type conversion و type assertion است. Type Conversion تبدیل بین دو نوع مشخص و سازگار است (مثل int(floatVal))، در حالی که Type Assertion استخراج نوع واقعی از داخل interface است. این دو مکانیزم کاملاً متفاوت کار می‌کنند و کاربردهای متفاوتی دارند.

2.2.4 بسته‌ی strconv: تبدیل‌های رشته‌ای-عددی

بسته‌ی strconv ابزار استاندارد Go برای تبدیل بین رشته‌ها و انواع عددی است. در PHP این تبدیل‌ها به‌طور خودکار یا با توابع ساده‌ای مثل intval() و strval() انجام می‌شوند. اما در Go هر تبدیل خطای احتمالی دارد که باید مدیریت شود. این طراحی عمدی است: هر جای ممکن است خطایی رخ دهد، کامپایلر شما را مجبور می‌کند آن را در نظر بگیرید.

الگوی رایج: در Go الگوی value, err := strconv.Atoi(input) به همراه if err != nil بسیار رایج است. هرگز خطای strconv را نادیده نگیرید — ورودی کاربر همیشه می‌تواند نامعتبر باشد. در PHP تابع intval("abc") بدون خطا عدد 0 برمی‌گرداند، اما در Go تابع Atoi("abc") خطا برمی‌گرداند.
تله‌ی مقایسه‌ی interface در Go: در PHP مقایسه‌ی $a == $b فقط مقادیر را مقایسه می‌کند، اما در Go دو مقدار interface{} تنها زمانی برابرند که هم نوع دینامیک و هم مقدار یکسانی داشته باشند. به‌علاوه، اگر مقدار زیرین interface از نوع non-comparable (مثل slice یا map) باشد، مقایسه‌ی == در زمان اجرا panic می‌کند. برای مقایسه‌ی ایمن مقدار زیرین، ابتدا با type switch یا comma-ok نوع را استخراج کنید.

2.2.5 تبدیل‌کننده‌های سفارشی

گاهی نیاز دارید تبدیل‌هایی فراتر از تبدیل‌های استاندارد انجام دهید — مثلاً تبدیل تاریخ از/به رشته، یا تبدیل نوع سفارشی. در Go دو روش اصلی برای این کار وجود دارد: تعریف متد String() روی نوع سفارشی، و استفاده از interface هایی مثل Stringer و TextUnmarshaler.

2.2.6 پیامدهای کارایی تبدیل‌ها

تبدیل نوع در Go عموماً بسیار سریع است اما برخی تبدیل‌ها هزینه‌ی پنهان دارند. تبدیل string به []byte و بالعکس کپی کامل داده ایجاد می‌کند. تبدیل Type Assertion از طریق interface مقداری overhead دارد چون باید جدول متدها را بررسی کند. و تبدیل‌های strconv شامل تجزیه‌ی رشته هستند که از تبدیل‌های مستقیم عددی کندترند.

2.2.7 PHP Type Juggling در برابر تبدیل صریح Go

همان‌طور که در ابتدای این بخش اشاره شد، PHP Type Juggling منبع بسیاری از باگ‌های ظریف است (مانند "hello" + 1 = 1 یا "foo" == 0 → true). نمودار زیر این تفاوت فلسفی را به‌صورت بصری کنار هم قرار می‌دهد و تبدیل‌های ایمن و ناایمن در Go را فهرست می‌کند.

2.2.8 سناریوهای عملیاتی

در پروژه‌های واقعی، تبدیل نوع یکی از رایج‌ترین عملیات‌هاست و درک صحیح آن از بروز باگ‌های پنهان جلوگیری می‌کند. در ادامه پنج سناریوی عملیاتی کلیدی را بررسی می‌کنیم که هر برنامه‌نویس Go باید به‌خوبی بشناسد.

این سناریوها شامل تبدیل رشته به عدد با مدیریت خطا، تبدیل بین انواع عددی، هزینه‌ی تبدیل []byte و string، استفاده از type assertion با interface و پیاده‌سازی Stringer سفارشی است. هر یک از این موارد در عمل با اهمیت بالایی مواجه هستند و تسلط بر آن‌ها کد شما را ایمن‌تر و کارآمدتر می‌کند.

  • تبدیل رشته به عدد با مدیریت خطا (strconv.Atoi): یکی از رایج‌ترین عملیات‌ها تبدیل ورودی کاربر از رشته به عدد است. در PHP تابع intval("abc") بدون خطا عدد 0 برمی‌گرداند اما در Go تابع strconv.Atoi("abc") خطا برمی‌گرداند. همیشه الگوی n, err := strconv.Atoi(input); if err != nil { ... } را رعایت کنید. این رویکرد الزامی تضمین می‌کند که ورودی نامعتبر هرگز به‌صورت خاموش نادیده گرفته نمی‌شود.
  • تبدیل بین انواع عددی به‌صورت ایمن: تبدیل int64 به int در سیستم‌های ۳۲ بیتی ممکن است باعث overflow شود. تبدیل float64 به int بخش اعشاری را حذف می‌کند. همیشه قبل از تبدیل بررسی کنید که مقدار در محدوده‌ی نوع مقصد قرار دارد. مثلاً if val > math.MaxInt32 { return error } قبل از int32(val) از overflow جلوگیری می‌کند.
  • هزینه‌ی تبدیل []byte ↔ string: هر تبدیل بین []byte و string یک کپی کامل داده ایجاد می‌کند. اگر در حلقه‌ی حلقه‌ی بحرانی بارها این تبدیل را انجام دهید، عملکرد برنامه به‌شدت افت می‌کند. در مسیرهای بحرانی از unsafe.Pointer برای تبدیل بدون کپی استفاده کنید — اما فقط وقتی مطمئن هستید داده تغییر نمی‌کند. در غیر این صورت، ساده‌ترین راه استفاده از []byte(s) و string(b) است.
  • استفاده از type assertion با interface: وقتی با interface{} یا any کار می‌کنید، همیشه از الگوی comma-ok استفاده کنید: val, ok := x.(string). این الگو از panic جلوگیری می‌کند و به شما امکان می‌دهد عدم تطابق نوع را به‌صورت ایمن مدیریت کنید. در type switch نیز هر نوع ممکن را پوشش دهید و default فراموش نشود.
  • پیاده‌سازی Stringer سفارشی: interface ی fmt.Stringer به نوع‌های سفارشی شما امکان نمایش متنی زیبا می‌دهد. وقتی متد String() string را روی نوع خود تعریف کنید، fmt.Println و log.Printf به‌طور خودکار از آن استفاده می‌کنند. این الگو در PHP معادل متد جادویی __toString() است اما در Go صریح‌تر و پیش‌بین‌پذیرتر عمل می‌کند.
نکته‌ی حرفه‌ای: تبدیل صریح نوع در Go یک ویژگی است نه محدودیت — این رویکرد از باگ‌های ظریفی جلوگیری می‌کند که PHP Type Juggling می‌تواند ایجاد کند. در PHP عبارت "0" == false مقدار true برمی‌گرداند و عبارت "foo" == 0 نیز true است! این رفتار غیرمنتظره منبع تعداد زیادی باگ‌های امنیتی در برنامه‌های PHP بوده است. در Go چنین مقایسه‌هایی امکان‌پذیر نیستند چون کامپایلر اجازه‌ی مقایسه‌ی انواع ناسازگار را نمی‌دهد. این سخت‌گیری در ابتدا ممکن است زمان‌بر به‌نظر برسد اما در بلندمدت از دسته‌ای از باگ‌های ردیابی‌نشده جلوگیری می‌کند و قابلیت اطمینان کد را به‌طرز چشمگیری افزایش می‌دهد.
