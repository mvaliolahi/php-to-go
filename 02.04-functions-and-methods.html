توابع و متدها ستون فقرات برنامه‌نویسی ساخت‌یافته هستند. برخلاف PHP که مبتنی بر کلاس‌ها و اشیاء است Go با یک ترکیب ساده اما قدرتمند از توابع، structها و اشاره‌گرها امکان طراحی برنامه‌های واضح، سریع و ایمن را فراهم می‌کند. در ادامه قدم به قدم با ساختار توابع و نحوه تعریف متدها روی structها، مدیریت حافظه با اشاره‌گرها، مفاهیم حوزه‌ی متغیرها، کلیدواژه defer و قابلیت پیشرفته جنریک‌ها آشنا می‌شوید.

توابع باید کوچک باشند. و بعد از آن کوچک‌تر هم باشند. اولین قانون توابع این است که کوچک باشند. دومین قانون این است که کوچک‌تر از آن باشند.

Uncle Bob مهندس نرم‌افزار و نویسنده | Clean Code

نکته‌ی حرفه‌ای: Go به‌ذات توابع کوچک و متمرکز را تشویق می‌کند. در PHP رایج است که یک متد بزرگ در کلاس (اصطلاحاً god-object) ده‌ها خط منطق شامل اعتبارسنجی، دسترسی به دیتابیس و قالب‌بندی خروجی را در خود جای دهد. اما در Go این مسئولیت‌ها به توابع مستقل با نام‌های صریح شکسته می‌شوند: Validate()، Save()، Format(). بازگشت چند مقداری ((result, error)) و defer جایگزین تو در روی توابع بلند می‌شوند و هر تابع فقط یک کار را به‌خوبی انجام می‌دهد.

تعریف تابع

تعریف تابع در Go بسیار واضح و منظم است. برخلاف PHP که نوع‌دهی پارامترها و مقدار بازگشتی اختیاری است در Go تعریف نوع پارامترها و نوع بازگشتی اجباری است. این باعث می‌شود که کد شما هم خواناتر شود و هم احتمال خطا کاهش یابد.

در این مثال تابع greet یک پارامتر از نوع رشته می‌گیرد و یک رشته به عنوان خروجی برمی‌گرداند.

بازگشت چند مقدار

Go یکی از معدود زبان‌هایی است که از بازگشت همزمان چند مقدار از تابع پشتیبانی می‌کند ویژگی‌ای که در PHP معمولاً باید با آرایه‌ها یا اشیاء شبیه‌سازی شود.

مثال بالا یک عدد و خطا برمی‌گرداند این امکان به شما اجازه می‌دهد بدون اینکه از روش‌های پیچیده استفاده کنید به سادگی خطاها را مدیریت کنید.

ارسال مقدار یا ارجاع

در Go وقتی یک مقدار به تابع ارسال می‌شود کپی آن مقدار به تابع داده می‌شود. به عبارت دیگر تغییر مقدار در داخل تابع روی مقدار اصلی تاثیری ندارد. اگر می‌خواهید مقدار اصلی را تغییر دهید باید آدرس آن را ارسال کنید و در تابع از pointer استفاده کنید که در بخش بعدی به تفصیل به این خواهیم پرداخت.

توجه داشته باشید که name* مقدار آدرس اشاره شده را می‌خواند یا تغییر می‌دهد و n& آدرس متغیر n را می‌گیرد. همانطور که می‌دانید در PHP شما با var$& مقدار را به صورت مرجع ارسال می‌کنید ولی در Go این مکانیزم واضح‌تر و صریح‌تر است.

توابع ناشناس

مانند PHP توابع در Go نیز first-class citizens هستند یعنی می‌توانند به متغیرها نسبت داده شوند یا به عنوان آرگومان به توابع ارسال شوند و یا به عنوان خروجی یک تابع بازگردانده شوند.

این ویژگی برای برنامه‌نویسی functional و استفاده از callbackها بسیار کاربردی است.

تله‌ی مهم: closure در Go متغیرها را by-reference capture می‌کند نه by-value. در مثال اشتباه بالا، همه‌ی goroutineها به همان متغیر i اشتراک دارند و چون حلقه احتمالاً قبل از اجرای goroutineها تمام می‌شود، مقدار i برابر ۳ خواهد بود. در PHP مشکل مشابهی با closureها وجود دارد اما با use ($i) مقدار کپی می‌شود. در Go باید متغیر را به عنوان پارامتر به تابع ناشناس بفرستید.
ساختار داخلی Closure در Go: وقتی closure متغیری را capture می‌کند، کامپایلر Go ساختاری پنهانی ایجاد می‌کند که شامل متغیرهای capture شده و اشاره‌گری به کد تابع است. متغیرهای capture شده روی heap قرار می‌گیرند (نه stack) تا از یک فراخوانی تابع به فراخوانی بعدی زنده بمانند. این جایی است که Escape Analysis کامپایلر Go تصمیم می‌گیرد یک متغیر را از stack به heap منتقل کند.

دیاگرام مقایسه‌ی Value Receiver در برابر Pointer Receiver

انتخاب بین value receiver و pointer receiver یکی از مهم‌ترین تصمیمات طراحی در Go است. در PHP همه‌ی متدها درون کلاس تعریف می‌شوند و $this همیشه به شیء فعلی اشاره می‌کند اما در Go این انتخاب صریح است و پیامدهای مستقیمی بر رفتار متد، کارایی و رضایت interface دارد. شکل زیر دو رویکرد را به‌صورت بصری مقایسه می‌کند و قواعد method set و تله‌های رایج را نشان می‌دهد.

سناریوهای عملیاتی متدها و Receiver

انتخاب نوع receiver تنها یک مسئله‌ی فنی نیست بلکه تصمیم طراحی است که بر کل معماری نوع تأثیر می‌گذارد. در PHP همه‌ی متدها به‌طور ضمنی از طریق $this به شیء اصلی دسترسی دارند اما در Go این انتخاب باید صریح و سازگار باشد. در ادامه سناریوهای عملیاتی رایج را بررسی می‌کنیم و بهترین روش‌ها را برای هر مورد ارائه می‌دهیم.

  • انتخاب بین value و pointer receiver: قانون ساده این است: اگر نیاز به تغییر وضعیت receiver دارید یا struct بزرگی دارید از pointer receiver استفاده کنید. اگر متد فقط داده می‌خواند و struct کوچک است (مانند time.Time یا Point) از value receiver استفاده کنید. مهم‌تر از همه: در یک نوع سازگار باشید — اگر حتی یک متد به pointer receiver نیاز دارد همه متدها pointer receiver باشند.
  • زنجیره‌ی متدها با pointer receiver: یکی از الگوهای قدرتمند در Go زنجیره‌ی متدها (method chaining) است. با بازگرداندن *Type از متدها می‌توانید فراخوانی‌ها را زنجیره‌ای کنید: builder.SetName("Ali").SetAge(30).Build(). این الگو در PHP با بازگرداندن $this انجام می‌شود اما در Go باید pointer receiver باشد تا تغییرات روی شیء اصلی اعمال شوند.
  • پیاده‌سازی interface با pointer receiver: اگر متدی با pointer receiver تعریف شود فقط مقدار اشاره‌گر (*T) آن interface را ارضا می‌کند نه مقدار مستقیم (T). بنابراین هنگام اختصاص مقدار به متغیر interface باید از اشاره‌گر استفاده کنید: var g Greeter = &User{}. این یکی از رایج‌ترین منابع خطای کامپایل برای برنامه‌نویسان PHP است.
  • الگوی سازنده با بازگرداندن اشاره‌گر: در Go الگوی idiomatic برای سازنده تابع NewX() است که اشاره‌گر برمی‌گرداند: func NewUser(name string) *User { return &User{Name: name} }. این الگو مزایای متعددی دارد: از تغییرات ناخواسته جلوگیری می‌کند چون فراخوان باید صریحاً اشاره‌گر را ارجاع دهد و سازگاری با pointer receiver تضمین می‌شود.
  • اجتناب از وضعیت اشتراکی قابل تغییر: وقتی چندین goroutine به یک struct دسترسی دارند value receiver طبیعتاً ایمن است چون روی کپی کار می‌کند اما pointer receiver نیاز به هماهنگی صریح دارد. از mutex یا channel برای محافظت از داده‌ی مشترک استفاده کنید. هرگز فرض نکنید که pointer receiver بدون هماهنگی ایمن است.
قانون طلایی — سازگاری در انتخاب Receiver: اگر حتی یک متد از نوع شما به pointer receiver نیاز دارد همه‌ی متدهای آن نوع باید pointer receiver باشند. این رویکرد سازگاری method set را حفظ می‌کند و از خطاهای عجیب با interface جلوگیری می‌کند. مخلوط کردن value و pointer receiver در یک نوع منبع رایج باگ‌هاست: نوع T برخی متدها را دارد و نوع *T همه را و این ناسازگاری فقط هنگام استفاده از interface آشکار می‌شود. به‌عنوان قاعده‌ی کلی: اگر شک دارید pointer receiver را انتخاب کنید.
