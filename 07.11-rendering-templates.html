رندر کردن قالب‌ها

ساختار داده و ارسال به قالب

قالب‌ها با استفاده از یک context معمولاً struct یا map داده‌ها را دریافت می‌کنند و بر اساس آن رندر می‌شوند. داده‌ها باید به گونه‌ای طراحی شوند که کاملاً قابل فهم و ساخت‌یافته باشند.

نقش نقطه (.) در قالب‌ها

نماد نقطه (.) در قالب‌های Go به داده‌های context فعلی اشاره دارد. وقتی tmpl.ExecuteTemplate(w, "layout.html", data) فراخوانی می‌شود، . به data اشاره دارد. در داخل {{ range .Items }} نقطه به هر عنصر از slice اشاره می‌کند. در داخل {{ with .User }} نقطه به مقدار .User تغییر می‌کند:

نکته: دستور {{ with }} دو کار انجام می‌دهد: مقدار را بررسی می‌کند (اگر خالی باشد بلوک اجرا نمی‌شود) و همزمان نقطه را به آن مقدار تغییر می‌دهد. این معادل ترکیب @if و @php($variable = ...) در Blade است.
یادداشت: تفاوت tmpl.Execute(w, data) و tmpl.ExecuteTemplate(w, "name", data) یک منشأ رایج سردرگمی است: Execute فقط قالب اصلی (بدون نام) را رندر می‌کند و اگر قالب‌ها با {{ define }} نام‌گذاری شده باشند، به‌تنهایی کار نمی‌کند. ExecuteTemplate به شما اجازه می‌دهد قالب مشخصی را با نام فراخوانی کنید — که در الگوی layout + content ضروری است (همیشه نام قالب پایه مثل "layout.html" را پاس بدهید، نه نام قالب محتوا). اگر قالب رندر نشد و خطای "not defined" گرفتید، اول با tmpl.DefinedTemplates() لیست قالب‌های موجود را چاپ کنید.

سناریوهای عملیاتی رندر قالب

رندر کردن قالب‌ها در پروژه‌های واقعی بسیار فراتر از فراخوانی ساده ExecuteTemplate است. شما با سناریوهای متنوعی مواجه خواهید شد که نیاز به درک عمیق‌تری از نحوه کار سیستم قالب‌سازی دارند. در این بخش مهم‌ترین سناریوهای عملیاتی را که هر توسعه‌دهنده Go باید بشناسد بررسی می‌کنیم. این سناریوها شامل رندر جداول پویا، رندر شرطی، الگوی لایه‌بندی، ساختارهای داده تودرتو و رفع اشکال خطاهای قالب هستند. هر یک از این الگوها در پروژه‌های عملی به کرات استفاده می‌شوند و بدون تسلط بر آن‌ها نوشتن برنامه‌های وب کارآمد امکان‌پذیر نیست.

  • رندر جداول پویا با range: نمایش لیست داده‌ها در جداول HTML یکی از رایج‌ترین نیازهاست. با {{ range .Items }} روی slice حلقه می‌زنید و هر عنصر را در یک ردیف جدول رندر می‌کنید. نکته مهم: در داخل range نقطه (.) به هر عنصر تغییر می‌کند، بنابراین {{ .Name }} به فیلد Name عنصر جاری اشاره دارد. اگر slice خالی باشد بخش {{ else }} اجرا می‌شود — از این ویژگی برای نمایش پیام «داده‌ای یافت نشد» استفاده کنید.
  • رندر شرطی با if: بخش‌هایی از قالب بر اساس شرایط نمایش داده می‌شوند. {{ if .IsAdmin }}...{{ end }} محتوای ادمین را نشان می‌دهد. {{ if .Flash }}...{{ end }} پیام فلش را نمایش می‌دهد. نکته: مقادیر صفر (0، ""، nil، false) همگی falsy ارزیابی می‌شوند. برای بررسی دقیق‌تر از {{ if eq .Status "active" }} یا {{ if ne .Count 0 }} استفاده کنید.
  • الگوی لایه‌بندی (Layout + Content): رایج‌ترین الگو برای ساختار صفحات وب. قالب لایه‌بندی شامل هدر، فوتر و اسلات محتوا با {{ block "content" . }}{{ end }} است. هر صفحه فقط بخش define "content" را تعریف می‌کند. وقتی ExecuteTemplate(w, "layout.html", data) فراخوانی می‌شود، قالب لایه‌بندی رندر شده و محتوای هر صفحه به صورت خودکار جایگذاری می‌شود. این الگو معادل @extends و @yield در Blade است.
  • رندر ساختارهای داده تودرتو: داده‌های واقعی اغلب ساختار تودرتو دارند: PageData.User.Email یا Order.Customer.Address.City. در قالب‌ها با {{ .User.Email }} به فیلدهای تودرتو دسترسی دارید. برای تغییر context به یک زیرساختار از {{ with .User }}...{{ end }} استفاده کنید — در داخل بلوک with نقطه به .User اشاره دارد و {{ .Email }} کافی است.
  • رفع اشکال خطاهای قالب: خطاهای رایج قالب شامل: "not defined" (قالب یا تابعی وجود ندارد)، "can't evaluate field" (فیلدی روی نوع نادرست فراخوانی شده)، و خطاهای partial write (بخشی از محتوا قبل از خطا ارسال شده). برای رفع اشکال: ابتدا نام قالب را با tmpl.DefinedTemplates() بررسی کنید. سپس نوع داده ارسالی را با fmt.Printf("%#v", data) چاپ کنید. در نهایت همیشه از buffer استفاده کنید تا از نوشتن جزئی جلوگیری شود.
نکته طلایی: قالب‌ها را یک بار در init() یا main() پارس کنید و شیء *template.Template را در متغیر سراسری ذخیره کنید. هرگز قالب‌ها را در هر درخواست HTTP مجدداً پارس نکنید. پارس کردن عملیاتی پرهزینه است که شامل خواندن فایل‌ها، تحلیل نحوی و ساخت درخت اجرایی است. تکرار این فرایند در هر درخواست نه تنها عملکرد را به شدت کاهش می‌دهد، بلکه احتمال خطاهای ناهمزمان (race condition) را نیز افزایش می‌دهد. الگوی صحیح: parse once, execute many — پارس یک بار، اجرای بارها.
