سرو کردن فایل‌های استاتیک

چکیده: این بخش سرو فایل‌های استاتیک با net/http را پوشش می‌دهد: FileServer، ServeFile و embed.FS. الگوی caching و ETag بررسی می‌شود. تفاوت با Nginx static serving و کاربردهای عملی پوشش داده می‌گردد.

سرو کردن فایل‌های استاتیک (CSS، JavaScript، تصاویر) یکی از ملزومات هر وب‌سروری است. Go به سادگی این کار را انجام می‌دهد اما در محیط production باید موارد امنیتی و بهینه‌سازی را رعایت کرد.

داخلی‌های http.FileServer: http.FileServer یک http.Handler است که از رابط fs.FS فایل‌ها را می‌خواند. این هندلر به صورت خودکار Content-Type را بر اساس پسوند فایل تنظیم می‌کند، از هدرهای Last-Modified و If-Modified-Since برای کش شرطی پشتیبانی می‌کند، و درخواست‌های دایرکتوری را به index.html هدایت می‌کند. اگر index.html وجود نداشته باشد، لیست فایل‌ها نمایش داده می‌شود که باید غیرفعال شود.

7.5.1 نقش StripPrefix

http.StripPrefix پیشوند مسیر را از URL درخواست حذف می‌کند قبل از اینکه به FileServer برسد. مثلاً درخواست /static/css/style.css به css/style.css تبدیل می‌شود. بدون این، FileServer به دنبال فایل static/css/style.css در دایرکتوری می‌گردد و آن را پیدا نمی‌کند.

7.5.5 نگاشت سیستم فایل به مسیرهای HTTP

یکی از مفاهیم کلیدی در سرو فایل‌های استاتیک، درک نحوه تبدیل ساختار دایرکتوری فایل‌ها به مسیرهای HTTP است. در PHP این کار معمولاً توسط وب‌سرور Nginx یا Apache انجام می‌شود و فایل‌ها مستقیماً از دیسک خوانده می‌شوند.

اما در Go فرآیند متفاوت است: http.FileServer از رابط fs.FS برای خواندن فایل‌ها استفاده می‌کند و هدرهای HTTP مناسب را به صورت خودکار تنظیم می‌نماید.

در نمودار زیر می‌توانید جریان کامل نگاشت از سیستم فایل تا پاسخ HTTP را مشاهده کنید، از جمله عملکرد http.StripPrefix برای حذف پیشوند مسیر، تشخیص خودکار Content-Type، و هدرهای کش:

در نمودار بالا جریان کامل سرو فایل‌های استاتیک نمایش داده شده است. سمت چپ ساختار دایرکتوری فایل‌ها، وسط عملکرد http.FileServer به عنوان آداپتور، و سمت راست پاسخ‌های HTTP نهایی قابل مشاهده است.

نکته مهم این است که http.StripPrefix پیشوند /static/ را از مسیر حذف می‌کند تا FileServer بتواند فایل صحیح را در دایرکتوری پیدا کند.

همچنین embed.FS برای اپلیکیشن‌هایی مناسب است که می‌خواهند همه فایل‌ها در باینری کامپایل شوند، در حالی که http.Dir برای فایل‌هایی که نیاز به بروزرسانی بدون ری‌استارت دارند مناسب‌تر است.

7.5.6 سناریوهای عملیاتی سرو فایل‌های استاتیک

در محیط‌های عملیاتی مختلف، سرو فایل‌های استاتیک نیازمند استراتژی‌های متفاوتی است. از اپلیکیشن‌های تک‌صفحه‌ای تا سیستم‌های مدیریت محتوا، هر سناریو چالش‌ها و راه‌حل‌های خاص خود را دارد. درک این سناریوها به شما کمک می‌کند تا بهترین تصمیم معماری را برای پروژه خود بگیرید. در ادامه پنج سناریوی عملیاتی رایج را بررسی می‌کنیم:

  • سرو SPA با embed.FS: اپلیکیشن‌های تک‌صفحه‌ای (React، Vue، Angular) معمولاً شامل فایل‌های HTML، CSS و JavaScript کامپایل‌شده هستند. با استفاده از embed.FS می‌توانید تمام این فایل‌ها را در باینری Go قرار دهید و یک فایل اجرایی واحد برای استقرار داشته باشید. برای مسیرهای SPA که توسط client-side router مدیریت می‌شوند، باید همه مسیرهای یافت‌نشده را به index.html هدایت کنید تا SPA بتواند مسیریابی را انجام دهد.
  • استراتژی‌های کش برای فایل‌های استاتیک: هدرهای کش نقش حیاتی در عملکرد دارند. برای فایل‌هایی که نامشان شامل هش محتوا است (مثل app.a1b2c3.js) از Cache-Control: public, max-age=31536000, immutable استفاده کنید. برای فایل‌های بدون هش از max-age کوتاه‌تر یا no-cache استفاده کنید تا مرورگر همیشه نسخه جدید را بررسی نماید. هدر ETag برای کش شرطی و کاهش پهنای باند بسیار مؤثر است.
  • سرو فایل‌های آپلودشده توسط کاربر: هرگز از http.FileServer برای سرو فایل‌های آپلودی استفاده نکنید. به جای آن از http.ServeContent() با Content-Type صریح استفاده کنید. این روش از اجرای قالب‌ها و دنبال کردن symlink ها جلوگیری می‌کند و کنترل کاملی روی هدرهای پاسخ به شما می‌دهد.
  • امنیت Content-Type: هدر X-Content-Type-Options: nosniff را همیشه تنظیم کنید تا مرورگرها نتوانند نوع محتوا را حدس بزنند. بدون این هدر، مهاجم ممکن است فایل HTML مخربی را با پسوند .png آپلود کند و مرورگر آن را به عنوان HTML اجرا کند. این حمله به MIME sniffing معروف است و با این هدر ساده قابل خنثی‌سازی است.
  • استفاده از CDN جلوی سرور Go: در محیط production با ترافیک بالا، قرار دادن یک CDN یا پروکسی معکوس مثل Nginx جلوی سرور Go بهترین روش است. CDN فایل‌های استاتیک را در نقاط مختلف جهان کش می‌کند و تأخیر را کاهش می‌دهد. سرور Go فقط درخواست‌های cache miss را پردازش می‌کند و بار سرور به شدت کاهش می‌یابد.
هشدار امنیتی: هرگز از http.FileServer برای سرو فایل‌های آپلودشده توسط کاربر استفاده نکنید. http.FileServer ممکن است قالب‌های Go را اجرا کند، symlink ها را دنبال کند و لیست دایرکتوری را نمایش دهد. به جای آن از http.ServeContent() با Content-Type صریح و سیستم فایل سفارشی استفاده کنید. نمونه کد:
