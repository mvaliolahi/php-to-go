Constructor و Factory

چکیده: Go constructor با تابع New ساده پیاده می‌شود و الگوهای پیشرفته‌تر factory و builder را شامل می‌شود. این بخش الگوهای رایج، option pattern و هشدار درباره‌ی over-engineering را پوشش می‌دهد. تفاوت با constructorهای PHP و static factory methods بررسی می‌شود.

در زبان‌هایی مانند PHP برای ساخت اشیاء معمولاً از متد ویژه‌ای به نام __construct() استفاده می‌شود که به‌طور صریح به عنوان سازنده شناخته می‌شود. اما در زبان Go هیچ سازنده از پیش تعریف‌شده‌ای برای structها وجود ندارد.

با این حال رویکرد رایج در Go برای ساختن و مقداردهی اولیه به structها تعریف توابع معمولی با نامی استاندارد مانند NewTypeName است.

این توابع نقش سازنده یا Factory Function را بازی می‌کنند و می‌توانند منطق مقداردهی اولیه، اعتبارسنجی یا تنظیم مقادیر پیش‌فرض را در خود جای دهند.

سازنده فقط باید مقادیر فیلدها را تنظیم کند و هیچ کار دیگری انجام ندهد. اگر نیاز به کار بیشتری دارید، یک متد کارخانه بسازید که سازنده را فراخوانی و سپس کار اضافی را انجام دهد.

نکته‌ی حرفه‌ای: الگوی NewX() در Go نسبت به __construct() در PHP برای تزریق وابستگی برتر است. در PHP سازنده مستقیماً در کلاس تعریف می‌شود و تغییر امضای آن شکستن تمام زیرکلاس‌هاست. اما در Go تابع NewUser(repo Repository, mailer Mailer) *User یک تابع مستقل است: می‌توان چندین سازنده با امضاهای مختلف داشت (NewUser، NewAdminUser، NewGuestUser) بدون اینکه ساختار struct تغییر کند. ضمناً وابستگی‌ها صریح هستند — با نگاه به امضای تابع فوراً می‌دانید چه چیزهایی لازم است، برخلاف Service Container در Laravel که وابستگی‌ها در پشت‌صحنه حل می‌شوند.

لازم به ذکر است شما حتی می‌توانید چندین تابع سازنده با رفتارهای متفاوت مثلاً NewAdminUser یا NewGuestUser بنویسید.

3.7.1 ترکیب Interface و Duck Typing

همان‌طور که در بخش ۳.۶ توضیح داده شد، interfaceها در Go به‌صورت ضمنی پیاده‌سازی می‌شوند (Duck Typing) و می‌توان آن‌ها را با هم ترکیب کرد.

این ویژگی‌ها نقش مهمی در طراحی سازنده‌ها ایفا می‌کنند: وقتی تابع سازنده‌ی شما یک interface برمی‌گرداند (نه struct)، مصرف‌کننده فقط به رفتار دسترسی دارد و پیاده‌سازی داخلی مخفی می‌ماند. این الگو به‌عنوان Factory Pattern شناخته می‌شود و در ادامه‌ی همین فصل بررسی خواهد شد.

چه زمانی از کدام الگو استفاده کنیم؟ از سازنده‌ی ساده NewX() وقتی استفاده کنید که struct کمتر از ۳ فیلد اختیاری دارد. از Functional Options وقتی استفاده کنید که فیلدهای اختیاری زیاد اما مستقل هستند. از Builder وقتی استفاده کنید که مراحل ساخت وابسته به هم هستند، اعتبارسنجی پیچیده لازم است یا ساخت باید تدریجی باشد (مثل SQL builder یا HTTP request builder).

3.7.4 چه زمانی در Go سازنده بنویسیم؟

در PHP هر کلاس همیشه یک constructor دارد (حتی اگر صریحاً تعریف نشده باشد). اما در Go ساخت struct بدون سازنده کاملاً معتبر است. پس چه زمانی باید تابع NewX() بنویسیم؟

بنویسید وقتی: — ۱. struct مقادیر اولیه‌ی پیچیده نیاز دارد (اتصال به دیتابیس، خواندن تنظیمات).

۲. اعتبارسنجی لازم است (بررسی اینکه فیلدهای ضروری تنظیم شده‌اند).

۳. فیلدهای unexported دارید که باید از خارج مقداردهی شوند.

۴. interface برمی‌گردانید نه struct — تا پیاده‌سازی داخلی مخفی بماند.

نیازی نیست وقتی: — ۱. struct فقط فیلدهای ساده و exported دارد.

۲. zero value معتبر و مفید است (مثل sync.Mutex{} یا bytes.Buffer{}).

۳. هیچ منطق مقداردهی خاصی وجود ندارد.

3.7.7 تزریق وابستگی با Constructor ها

در PHP تزریق وابستگی (DI) معمولاً به‌صورت خودکار توسط Service Container انجام می‌شود. اما در Go تزریق وابستگی صریح و دستی است — و این یک مزیت محسوب می‌شود:

نکته: اگر تزریق وابستگی صریح بیش از حد طولانی شد، از الگوی Functional Options یا Builder استفاده کنید. اما هرگز یک Container/DI framework خودکار اضافه نکنید — این ضد الگوی Go است. شفافیت وابستگی‌ها یک مزیت است نه مشکل.
نکته‌ی حرفه‌ای — قرارداد نام‌گذاری NewX() و قانون zero-value: در Go برخلاف PHP که __construct() یک قرارداد زبانی است، نام NewX() فقط یک قرارداد نوشتاری است که در کتابخانه استاندارد ریشه دارد (مثل errors.New، http.NewServeMux، time.NewTimer). همیشه از پیشوند New استفاده کنید، نه Create، Make یا Build. دو استثنای مهم وجود دارد: ۱) وقتی zero value معتبر است، سازنده ننویسید (مثل sync.Mutex{} یا bytes.Buffer{} که کاملاً کاربردی هستند)؛ ۲) وقتی چند سازنده با رفتار متفاوت لازم دارید، از پیشوندهای توصیفی استفاده کنید (مثل NewAdminUser، NewGuestUser). رعایت این قراردادها باعث می‌شود کد شما برای دیگر Go کارها آشنا و قابل پیش‌بینی باشد.

3.7.8 مقایسه‌ی الگوی NewX() و مقدار صفر

یکی از مهم‌ترین تصمیماتی که در طراحی API یک پکیج Go باید بگیرید این است که آیا کاربر باید شیء را با NewX() بسازد یا مستقیماً با X{} مقداردهی اولیه کند. این تصمیم به ماهیت struct و نوع استفاده‌ی مورد انتظار بستگی دارد.

برخی structها مانند sync.Mutex و bytes.Buffer بدون هیچ مقداردهی اولیه‌ای کاملاً کاربردی هستند و مقدار صفر (zero value) آن‌ها معتبر و مفید است.

اما اکثر structها به مقداردهی اولیه نیاز دارند و استفاده از NewX() بهترین روش برای اطمینان از صحت وضعیت اولیه شیء است.

نمودار بالا سه الگوی اصلی مقداردهی اولیه در Go را مقایسه می‌کند. الگوی NewX() در سمت چپ با رنگ سبز نمایش داده شده و مناسب مواردی است که اعتبارسنجی، مقدار پیش‌فرض یا مدیریت خطا نیاز دارید.

الگوی مقدار صفر در سمت راست با رنگ نارنجی نشان داده شده و فقط برای structهایی مناسب است که مقدار صفر آن‌ها معتبر و مفید است مانند sync.Mutex و bytes.Buffer.

الگوی Factory در پایین با رنگ آبی مشخص شده و وقتی استفاده می‌شود که بخواهید بر اساس یک پارامتر پیاده‌سازی متفاوتی از یک interface برگردانید.

در PHP فقط یک سازنده __construct() اجباری دارید اما در Go آزادی انتخاب بین این الگوها وجود دارد و باید بر اساس نیاز پروژه تصمیم بگیرید.

3.7.9 سناریوهای عملیاتی

  • سازنده با اعتبارسنجی: وقتی struct شما فیلدهایی دارد که باید حتماً مقدار معتبر داشته باشند از NewX() استفاده کنید. تابع سازنده ورودی‌ها را بررسی می‌کند و در صورت نامعتبر بودن خطا برمی‌گرداند. این الگو تضمین می‌کند که هیچ شیء نامعتبری ساخته نمی‌شود و مصرف‌کننده مجبور است خطا را مدیریت کند. مثلاً NewServer(addr string) (*Server, error) تضمین می‌کند که سرور همیشه یک آدرس معتبر دارد.
  • الگوی Factory برای برگرداندن interface: وقتی می‌خواهید پیاده‌سازی داخلی را مخفی کنید و فقط interface را آشکار کنید از الگوی Factory استفاده کنید. تابع NewStorage(config Config) Storage بسته به تنظیمات ممکن است یک redisStorage یا memStorage برگرداند اما مصرف‌کننده فقط با Storage کار می‌کند و نیازی ندارد بداند کدام پیاده‌سازی استفاده شده. این الگو encapsulation قوی‌ای فراهم می‌کند.
  • الگوی Functional Options برای سازنده‌های پیچیده: وقتی struct تعداد زیادی فیلد اختیاری دارد از WithX استفاده کنید. هر تابع WithX فقط یک جنبه‌ی پیکربندی را تنظیم می‌کند و ترتیب آن‌ها اهمیتی ندارد. مثلاً NewServer(WithPort(8080), WithTimeout(30*time.Second)) بسیار خواناتر از ارسال ده پارامتر به تابع سازنده است. اضافه‌کردن option جدید بدون تغییر رابط سازنده امکان‌پذیر است.
  • الگوی struct خصوصی + interface عمومی: یکی از قوی‌ترین الگوهای Go این است که struct را unexported (حرف کوچک) تعریف کنید اما interface آن exported باشد. این کار به شما اجازه می‌دهد پیاده‌سازی داخلی را آزادانه تغییر دهید بدون اینکه مصرف‌کنندگان خارجی متوجه شوند. تابع سازنده interface برمی‌گرداند نه struct و مصرف‌کننده فقط به رفتار وابسته است نه ساختار.
  • الگوی Builder برای ساخت چندمرحله‌ای: وقتی ساخت شیء شامل مراحل وابسته به هم یا اعتبارسنجی پیچیده است از الگوی Builder استفاده کنید. مثلاً ساخت HTTP client با base URL، timeout، retry و headerهای سفارشی. الگوی Builder اجازه می‌دهد هر مرحله به‌صورت تدریجی اضافه شود و در نهایت تابع Build() تمام اعتبارسنجی‌ها را انجام دهد.
قانون طلایی سازنده‌های پیچیده: وقتی تعداد پارامترهای اختیاری زیاد است از الگوی Functional Options استفاده کنید: NewServer(WithPort(8080), WithTimeout(30*time.Second)). این الگو سه مزیت کلیدی دارد: اول اینکه هر option مستندات خود را دارد و IDE آن‌ها را نشان می‌دهد. دوم اینکه اضافه‌کردن option جدید بدون تغییر رابط سازنده امکان‌پذیر است و سازگاری عقب‌ (backward compatibility) حفظ می‌شود. سوم اینکه مقادیر پیش‌فرض در خود تابع سازنده تعریف می‌شوند و مصرف‌کننده فقط مواردی را که می‌خواهد تغییر دهد مشخص می‌کند. این الگو در کتابخانه استاندارد Go و پروژه‌های بزرگ مانند gRPC و Kubernetes به‌وفور استفاده شده است.
