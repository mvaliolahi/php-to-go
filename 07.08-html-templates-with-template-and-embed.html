استفاده از قالب‌های HTML با پکیج html/template و embed

در توسعه‌ی وب، نمایش صحیح داده‌ها در صفحات HTML اهمیت زیادی دارد.

در Go برای ایجاد صفحات وب پویا از پکیجی به نام html/template استفاده می‌شود.

این پکیج امکان جدا کردن منطق برنامه‌نویسی از Presentation را مشابه template engine هایی مثل Laravel Blade فراهم می‌کند, همانطور که در فصل های قبل اشاره شد از Go 1.16 به بعد ابزار جدیدی به نام embed نیز معرفی شد که به شما اجازه می‌دهد فایل‌هایی مانند قالب‌های HTML، CSS یا فایل‌های پیکربندی را مستقیماً درون فایل binary برنامه جاسازی کنید.

این ویژگی برای توزیع ساده‌تر، امنیت بالاتر، و حذف وابستگی به فایل‌های خارجی بسیار مفید است.

Go دارای دو پکیج برای قالب‌سازی است:

text/template : مخصوص داده‌های متنی مانند ایمیل یا فایل‌های متنی. هیچ ایمن‌سازی‌ای انجام نمی‌دهد.

html/template : مخصوص HTML است و به طور خودکار داده‌های خروجی را در برابر حملات XSS escape می‌کند. در برنامه‌های وب همیشه باید از html/template استفاده کنید تا داده‌های کاربر به طور ایمن در HTML نمایش داده شوند.

7.8.6 سناریوهای عملیاتی قالب‌ها

در پروژه‌های واقعی وب، استفاده از سیستم قالب‌سازی Go فراتر از یک رندر ساده است. شما با سناریوهای متنوعی مواجه خواهید شد که درک عمیق‌تری از ابزارهای موجود نیاز دارند. در ادامه مهم‌ترین سناریوهای عملیاتی که هر برنامه‌نویس Go باید بشناسد را بررسی می‌کنیم.

این سناریوها شامل الگوهای وراثت قالب، قالب‌های بخشی قابل استفاده مجدد، توابع سفارشی، کش قالب‌های پارس‌شده و جلوگیری از حملات XSS هستند. تسلط بر این الگوها به شما کمک می‌کند برنامه‌های وب تمیزتر، امن‌تر و قابل نگهداری‌تری بنویسید.

  • وراثت قالب (Template Inheritance): در Go برخلاف Laravel Blade که @extends دارد، از {{ block }} و {{ template }} برای وراثت استفاده می‌شود. قالب پایه با {{ block "content" . }}{{ end }} یک اسلات تعریف می‌کند و قالب‌های فرزند با {{ define "content" }}...{{ end }} آن را پر می‌کنند. این الگو معادل @yield و @section در Blade است اما با تفاوت مهمی: در Go همه قالب‌ها باید همزمان پارس شوند تا ارتباط بین define و template برقرار شود.
  • قالب‌های بخشی (Partial Templates): قطعات تکراری مثل هدر، فوتر، منوی ناوبری و کارت محصول را در فایل‌های جداگانه تعریف کنید. با {{ template "header" . }} آن‌ها را در هر قالبی فراخوانی کنید. نکته مهم: حتماً نقطه (.) را پاس دهید تا داده‌های context به قالب بخشی منتقل شود. بدون پاس دادن نقطه، قالب بخشی به هیچ داده‌ای دسترسی نخواهد داشت.
  • توابع سفارشی (FuncMap): وقتی عملیاتی مثل فرمت تاریخ، تبدیل واحد پولی، برش رشته یا محاسبات ساده در قالب‌ها نیاز است، از template.FuncMap استفاده کنید. توابع ثبت‌شده باید حداکثر یک مقدار برگردانند یا یک مقدار و یک خطا. مهم‌ترین نکته: FuncMap باید قبل از ParseFS یا ParseFiles ثبت شود، وگرنه قالب‌ها نمی‌توانند توابع را پیدا کنند و خطای not defined دریافت می‌کنید.
  • کش قالب‌های پارس‌شده: پارس قالب‌ها عملیاتی پرهزینه است و نباید در هر درخواست تکرار شود. الگوی صحیح: یک بار در init() یا main() قالب‌ها را پارس کنید و شیء *template.Template را در متغیر سراسری ذخیره کنید. سپس در هر درخواست فقط Execute را فراخوانی کنید. این کار عملکرد برنامه را به شدت بهبود می‌بخشد و از خطاهای زمان‌اجرای ناشی از پارس مکرر جلوگیری می‌کند.
  • جلوگیری از XSS با خودکار-فرار (Auto-Escaping): پکیج html/template به صورت خودکار همه مقادیر را بر اساس context فرار می‌دهد. در <p>{{.Value}}</p> کاراکترهای خطرناک HTML-escape می‌شوند. در href="{{.URL}}" مقدار URL-encoded می‌شود. در <script>{{.Data}}</script> مقدار JS-escaped می‌شود. فقط وقتی مطمئنید محتوا امن و کنترل‌شده است از template.HTML برای دور زدن فرار خودکار استفاده کنید.
نکته طلایی: همیشه برای خروجی HTML از html/template استفاده کنید، هرگز از text/template. پکیج html/template به صورت خودکار مقادیر را escape می‌کند و از حملات XSS جلوگیری می‌کند. پکیج text/template هیچ ایمن‌سازی‌ای انجام نمی‌دهد و استفاده از آن برای HTML معادل باز گذاشتن در برای مهاجمان است. حتی اگر فکر می‌کنید ورودی کاربر خطرناک نیست، همیشه html/template را انتخاب کنید — هزینه اضافی ندارد اما امنیت تضمین‌شده‌ای ارائه می‌دهد.
خلاصه‌ی نکات کلیدی:
  • html/template با auto-escaping XSS
  • template.ParseFS از embed.FS
  • template.Execute با data context
  • define و template برای reuse
  • context-aware escaping (HTML، JS، URL)
